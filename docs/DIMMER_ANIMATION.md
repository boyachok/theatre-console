## Где настраивать

Ячейка **DIM конкретного прибора в конкретном шаге → «Анимация DIM» →
«Включить анимацию»**. Настройки независимы у всех12каналов/приборов/шагов,
копирование шага копирует их без alias. Значок волны в матрице обозначает динамику.
Кривую можно смотреть как иллюстрацию без включения LIVE. Старые сцены без поля
`animation` — обычная статика; существующая яркость/фейды сохраняют смысл.

| Параметр | Семантика |
|---|---|
| Функция | Статика, синус, квадрат, рамп, рандом |
| Яркость ячейки | Верхняя амплитуда B,0–100%; B=0 всегда нулевой выход |
| Период |0.02–3600с, скорость задаётся периодом, не UDP-частотой |
| Фаза |0–360°,360=0; хранится с шагом0.1°; отсчёт от начала сцены |
| Seed (вместо фазы у random) | целое0–4294967295; одинаковый seed даёт повторяемый рисунок |
| **Нижний уровень** | процент от амплитуды, не абсолютный PWM; B40/floor25 →10–40% |
| **Заполнение квадрата** | процент периода ВКЛ; короткие вспышки/строб;0% минимум,100% максимум |
| **Вершина рампа** |0% спад,50% треугольник,100% подъём; промежуточные значения асимметричны |
| **Плавность random** |0% sample-and-hold;100% плавный smoothstep весь период;25% переход в первой четверти, затем удержание |

Период — логарифмический фейдер от20мс до часа, остальные проценты/фаза — линейные.
Рядом текстовое поле без spinner/wheel-adjust; seed можно ввести или сменить кнопкой.
Пример: sine/B70/period6/floor15 — мягкое дыхание; квадрат/B100/period0.1/duty10 —
короткий строб; ramp/apex30 — быстрый подъём/медленный спад; random/period2/smooth100 —
плавное мерцание. Для волн на нескольких DIM задавать сдвиги фаз0/90/180/270°.

## Исполнение и переходы

Все функции вычисляются **локально на slave**, не потоком готовых PWM по сети.
НесущаяPWM остаётся25кГц (8LEDC+4MCPWM), модулятор получает расчётный шаг1мс.
Это best-effort loop сWi-Fi/flash: **не обещание точного1мс импульса**. Квадрат
при ненулевой скважности квантует расчётную ширину не меньше1мс; реальную ширину/
джиттер/максимальную пригодную частоту проверяют осциллографом и нагрузкой.
Стробоскопы могут провоцировать фотосенситивные реакции; предупреждение есть в UI.

- Новый шаг, back/first, recovery или новый run начинают анимацию с заданной фазы.
- LIVE-правка яркости/floor/duty/smooth не перезапускает фазу. Смена периода
  сохраняет долю текущего цикла и его номер; скорость меняется без скачка позиции.
- Смена функции, фазы или seed начинает соответствующий новый рисунок. Правки
  другого DIM/звука/реле не ретаргетят неизменившийся канал и его фейд.
- Повтор того же RUN/PREVIEW каждые200мс не сбрасывает таймер/RNG/фейд.
- Random — хеш(seed,cycle), не общий rand(): порядок каналов/частота tick/пропущенные
  тики не потребляют чужую последовательность. Есть обработка millis wrap без цикла
  по каждой пропущенной миллисекунде.
- Фейды смешивают вычисленный достигнутый уровень с новым динамическим сигналом,
  не дают скачка при animated→static. Направление fade определяется верхним уровнем.
- OFF редактора не STOP: принятая локальная анимация продолжает работать; правки
  синхронизируют память без GO. Явный ALL_OFF гасит12каналов и не отменяется повтором.

**Фаза локальна в пределах прибора.** Общего точного clock/executeAt между ESP
нет: старт разных slave разнесён приёмом/10мс слотами. Гарантий синфазного строба
между платами эта фича не добавляет. Веб-превью — модель, не датчик PWM/света.

## Формат/миграция/совместимость

JSON schemaVersion1 сохранён. Опциональный `DimmerCue.animation` не дописывается
автоматически в старый draft/неизменяемую публикацию; fingerprint старого snapshot
не меняется от открытия/экспорта. Отключение анимации сохраняет её настройки в JSON,
но компилирует прежний статический DIM `[value,inMs,outMs]`. Активный DIM имеет
9чисел: `[value,inMs,outMs,mode,periodMs,phaseOrSeed,floor,duty,smooth]`.
Валидация в UI и backend атомарно отклоняет mode/NaN/ranges/bad period/seed.

**Score protocol8:** RUN44B без значений по-прежнему запускает индекс/версию/CRC
локального плана. Cue314B (старый170B prefix +12×12B animation), STORE/PREVIEW358B.
Wi-Fi LAN payload max512B, один UDP datagram, без IP-фрагментации для обычногоMTU1500.
RUN/repeat200мс/счётчик master/R/1/service72B не менялись. По пути обновлена whitelist
LAN для optional UART116B: раньше0.7.9 codec знал extension, но transport пропускал
только100B; теперь это проверяется и транспортным тестом, не одним codec-тестом.
Архивные control/wifi04/ESP-NOW профили не менялись.

Новые capability **P/8 regular, P/9 helmet**. Старые0.7.9 P/6/P/7 не объявляются
score8-ready; indexed GO ждёт все назначенные планы на совместимых firmware.
Поэтому для стенда нужны **master+тестовый slave0.7.10**, пульт0.7.8 менять не нужно.
Для полного опубликованного спектакля потребуются все назначенные score8-узлы;
одна оставленная в сети плата не даёт готовность за остальные назначения.

Старый `/slave-score.bin` с16B header/reserved0 и170B cue проверяется по точному
размеру/CRC, конвертируется в RAM с нулевыми animation и новым planCRC. При boot
старый файл не стирается/не перезаписывается. Новый STORE записывает header/reserved8
и314B cue через временный файл/rename. Unknown/truncated/corrupt cache не исполняется.
Master восстанавливает старые compiled d3 из `/published.json`; опубликованный
номер/снимок workspace сохраняется, **planCRC закономерно меняется** из-за нового
двоичного формата. До готовности всех назначенных планов автоматического GO нет.
