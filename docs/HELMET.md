По разрешению установлен0.8.3 с gateфиксом DRY/mix0 и диагностикойgate.
Новые boot/MAC/role/версия проверены. Наmaster383 сохранены полные4пресета
«en»,«жен»,«муж»,«рэп» и рабочие параметры, оба банка до/после совпали.
Saved/appliedSound шлема сохранился; после автономного reboot отправлен явныйSTOP

## История первой USB/OTA установки

C0:4E:30:36:C6:88 установлен0.8.1 app-onlyUSB; новые boot/MAC/роль/версия и
HTTP status/OTAстраница192.168.50.21 проверены. Настройки/банк/разметка сохранены.
Позднее выполнен реальный app-onlyOTA0.8.1→0.8.2, новый boot и переключение
app0→app1 проверены. В master draft/publication380 сохранены полные2пресета
«Голос 1»/«Роботик жен», selected=voice-default; workspace и оба банка до/после OTA
совпали. Сохранённый/применённый профиль шлема тоже совпал. Это не сравнение физического звука.

Первая установка новой OTA-возможности на существующий0.7.19 требует USB.
Далее: `http://<IP шлема>/` → helmet `.bin`, либо
`EXPECTED_MAC=C0:4E:30:36:C6:88 ./deploy ota helmet 192.168.50.21`.
Проверки token/MAC/role/Origin, заголовка ESP32-S3, marker helmet и размера фактического
следующего OTA-слота. Marker не является криптографической подписью; только доверенная LAN.

Во время OTA звук/свет останавливаются, новые RUN/PREVIEW/STORE и USB d/b/L отвергаются.
Текущие startup-настройки сначала сохраняются; при ошибке сохранения OTA не начинается.
Коммит образа только после полного multipart POST. Ошибка/обрыв/тайм-аут оставляют STOP,
не возобновляют старую сцену; новая команда или reboot действуют по прежнему контракту.
Успешный reboot загружает сохранённый автономный звук/свет. Партитура, старый банк,
NVS и таблица разделов не заменяются; обновляется только приложение.

USB helper теперь app-only: полный16MB backup, явная EXPECTED_MAC, выбор текущего
слота по OTAdata CRC, ограничение его размером, verify-flash и побайтовая проверка
boot/table/NVS/OTAdata до reboot. Обычный deploy больше не заменяет разметку шлема.
`/api/status` и `/api/helmet/status` содержат token, bootId, otaSupported/busy/error,
текущий и следующий адреса app, реальный размер слота. HTTP-парсинг/сокеты вынесены
в отдельную задачу; DSP/I2S на своём ядре. Без AP, без отдельного редактора пресетов.

Native OTA-тесты и SDK-сборка пройдены, образ помещается в старый слот1.25MiB;
перваяUSBустановка, HTTPстраница и реальный uploadOTA0.8.2 проверены.
В операцииhelmetOTA master/slave/PWM не обновлялись.

## Пины и звук

- INMP441: VDD3V3, SCK GPIO4, WS GPIO5, SD GPIO7, L/R logic GND.
- PCM5102A: BCK GPIO4, LCK GPIO5, DIN GPIO6; SCK logic GND; VIN внешние5В
  согласно проверенной пользователем схеме из Robot Voice. Нельзя давать5В на микрофон/ESP GPIO.
- Лента DATA GPIO47, onboard status GPIO48. RGB/GRB400/800кГц и1–1024точки,
  реальная доступность большой ленты зависит от внутренней памяти и её DMA-буфера.
- Локальный I2S0 full-duplex48кГц,32-bit slots, mono microphone left → stereo DAC.
  Аудио task priority6/core1/16KB, управление сетью/лентой core0/12KB. Arduino loop
  не обрабатывает сеть параллельно вторым владельцем. DMA I/O не блокирует control task.

`helmet/voice/` — неизменённые восемь DSP/codec/settings заголовков и layout preset_bank.h из пользовательского
`~/Downloads/ESP32-Robot-Voice-v5.9.0/robot_voice/`. Их исходная legacy-RMT лента,
AP, веб-сервер и NVS UI не копируются. Порт I2S/DSP обёрнут в `helmet/voice_engine.h`
для ESP32 core3.3.11 вместо исходного2.0.9. Сохранены ring,12-band vocoder, YIN/PSOLA
autotune, monotone robot и speech chip; входные фильтры, gate, мягкое переключение,
lookahead limiter. TEST-tone не допускается сценовым wire. Введён отдельный численный
тест настоящих движков, но субъективное совпадение и задержка на новом устройстве
ещё не измерены. PSOLA имеет собственную задержку2048сэмплов, limiter96сэмплов + DMA;
это не обработка с нулевой задержкой. Исходный README архива частично относится кv4;
перенос ориентирован на реальные заголовки и DESIGN.md5.9.

## Общий звук, индивидуальный свет

У Device один VoiceBank: до8именованных пресетов, выбранный ID и необязательные
текущие working-настройки. В окне «Настройки шлема» редактируются все параметры,
выбор/переименование/Save/Save As/Delete (последний не удаляется). Детали звука
по умолчанию свёрнуты. Bank и working сохраняются в JSON проекта/бэкапа; старый
пользовательский банк источника не импортируется — пользователь выбрал настройку заново.

В сцене для голоса только voiceOn; громкость и DSP общие для шлема во всех сценах.
Компилятор повторяет один выбранный полный звук во всех cue данного устройства,
чтобы локальная flash-партитура была самодостаточна. Это не редактируемые копии
пресета в разных сценах: изменение Device одинаково перекомпилирует все cue.
Bank живёт на master/в JSON; шлему достаточно активного профиля в каждом своём cue.

LIVE немедленно применяет изменения через обычный guarded RAM draft/PREVIEW master.
OFF редактирует/синхронизирует хранилище без GO, как для остальных исполнителей.
Банк не пишет NVS шлема на каждое движение ползунка. STORE не включает звук/свет.

Лента в каждой сцене имеет отдельный снимок параметров выбранного FX (`strip.settings`).
Редактирование справа не меняет библиотеку/другие сцены. Старые проекты без снимка
читают прежний effectId. Явный hold означает продолжение предшествующего FX; новый
helmet cue по умолчанию STOP. При преобразовании standard→helmet пустые hold заменяются
на STOP; уже авторские play сохраняются. Голос и свет включаются независимо.

## Состояния

После питания **звук и лента включаются автономно** с последними применёнными
настройками. Отсутствие Wi-Fi/master не мешает старту. Это отдельный bootstrap-профиль,
не автоматическое выполнение первого/последнего номера сцены; status показывает standalone,
а step=null. Локальный план читается из flash, но сам не перелистывается.

`helmet-start/defaults` — атомарный111B NVS-record с magic/version/CRC. Изменения принятого
voice/светового play запоминаются после2с без изменений, одинаковые повторы не пишут flash.
OFF/STOP не запоминаются как постоянное выключение на следующее питание: до следующей
команды они держат OFF, при новом питании снова включается bootstrap. Потеря/возврат
связи НЕ отменяют OFF. Световой STOP не заменяет последнюю конфигурацию play. Если запись
не удалась, статус defaultsSaved=false, повтор не чаще30с; повреждённый/future record
не перезаписывается автоматически. Несохранённый/неприменённый черновик master сам не
попадает в startup defaults.

На первом запуске без record читается только активный валидный профиль старого Robot Voice
NVS (банк сохраняется неизменённым), иначе dry/gain8/volume15%. Старый TEST-tone не запускается.
Первый свет — синий waiting,60точек,10%,width15%,cycle4с; дальше сохраняется последний play.
На установленной плате сохранённый bodj: ring349Гц/gain0.9/volume100%; это не импорт всего
старого банка в JSON master. Общий пресет всех сцен задаёт master, его принятые настройки
переопределяют bootstrap и сохраняются для следующего питания. RUN44B выбирает CRC-bound локальный cue;
полного сетевого fallback на опубликованную сцену нет. Нет автономного перелистывания
и проигрывания пропущенной истории. STOP/ALL_OFF/MAINTENANCE выключают voice+strip;
повтор/одинаковое recovery не отменяют STOP. Идентичное восстановление активной сцены
не сбрасывает анимацию/аудиодвижок. Потеря Wi-Fi не выключает уже принятые состояния.

Микрофон продолжает считываться при выключенном speaker, чтобы свет мог реагировать
независимо от voiceOn. Внешнего аудиопотока через master нет.

## Общие FX всех лент

Существующие wave/fill/static плюс waiting,disco,alarm,loading используют один
`console/strip_animation.h` и соответствующий браузерный renderer. Count адаптирует
геометрию; loading симметричен для нечётного/чётного count и одной точки.

- Ожидание: мягкая полоса отражается от краёв, width%, цвет, время полного цикла.
- Дискотека: палитра (радуга/тёплая/холодная), движение полос, плотность, искры,
  скорость и общая яркость.
- Тревога: красный строб, управляемый пространственный/временной шум, скорость/яркость.
- Загрузка: циклические полосы из центра к краям, плотность/width/цвет/скорость.

AudioReactive открывает foreground по уровню собственного микрофона шлема, отдельные
threshold/release и фон color/brightness/enabled. Фон работает только при активной
ленте, не после STOP/в пустой сцене. На обычном slave нет микрофона: компилятор явно
отключает реактивный модификатор и воспроизводит общий FX обычно, без имитации звука.
Browser без реальной свежей телеметрии не генерирует fake microphone; возможен только
фон. RMT async, refresh не чаще33мс (реальная длительность ленты может ограничить FPS).
Строб применять с учётом фотосенситивности.

## Wire, версии и миграция

Score12, regular P/16, helmet P/17. Cue468B, STORE/PREVIEW512B (ровно LAN payload limit),
RUN44B без изменений. Прежний393B prefix сохранён: StripOptions16B+VoiceProfile59B
в конце. Старые cache7–11 проверяются по старому размеру/CRC и расширяются только
в RAM; файл не переписывается/не стирается при boot. Immutable publication JSON не
мигрирует сам. Wire-профиль строго проверяет finite/диапазоны всех параметров.

Новое исполнение требует master и всех назначенных исполнителей с поддержкой score12.
Старые P/14–15 не объявляются готовыми, даже если эффекты не используются. Remote0.7.8
R/1 может остаться. Подготовленная0.7.14 хранится отдельно и не была прошита/перезаписана.

Optional VoiceReport64B проверяется master по роли helmet, назначенной MAC, сессии,
boot и порядку uptime. Через master идут реальные input/output RMS, DSP load,
ошибки/late/limiter/captured/queued frames, ready/enabled/age. Это не proof звука
из динамика или точной end-to-end latency. Offline UI не сохраняет meter как свежий.

## Проверено и что остаётся

Native ASan/UBSan: настоящий DSP пяти алгоритмов finite/stereo/bounded output,
микрофон при mute, GPIO/RMT renderer всех mode/count, reactive release/background/STOP,
cache11 RAM migration; helmet firmware с mock I/O: local storage/index/ACK/STOP/link hold.
TS: общий bank во всех сценах, snapshot-свет, JSON, границы, симметрия и palette.
Browser: реальная production сборка с mock master, preset save/rename/смена,
LIVE/OFF/no-hidden-GO, per-scene FX/reactivity и mobile320px. Реальные четыре toolchain
сборки не заменяют испытания микрофона/ЦАП/усилителя и ленты вместе.

На C0:4E:30:36:C6:88 сохранены старые bootloader/table/NVS: app-only0x10000,
старый app0 размером0x140000. Для планов используется прежний **пустой** spiffs-раздел
0x290000/0x160000, форматированный LittleFS без замены таблицы. `mountShowFS(label)`
по-прежнему отказывается стирать непустой повреждённый раздел. Проверены digest,
MAC/version/новый boot, автономный старт без master, STOP и второй reboot с теми же
параметрами; исходная таблица совпала побайтно, CRC старого банка1397020606 сохранён.
Нельзя запускать обычный USB-deploy с новой таблицей на эту плату вслепую: он пишет
разметку, в отличие от выполненного app-only обновления.

Перед прошивкой: MAC/роль, полный flash и актуальная партитура/привязки; только явно
разрешённая плата. После — фактическая версия/новый boot. Первое прослушивание с малой
громкостью; отдельно проверить все алгоритмы, Wi-Fi/ленту при речи, шум/свист/питание,
уровни, DMA counters, нагрузку CPU и сохранение сцены. 0.7.16 установлена только на указанную плату; звук/свет на слух/визуально подтверждает пользователь.
