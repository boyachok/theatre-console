# Пульт0.8.4: батарея1S / двухкнопочная диагностика (подготовлено, НЕ установлено)

## Подключение

Одна обычная Li-ion18650, заряд до4.2В, обычная НЕизолированная повышайка до5В.
GPIO13/14 кнопки и48 LED не меняются. Новый GPIO4 = ADC1, input-only для батареи.

```
Защищённый + аккумулятора ПОСЛЕ выключателя, ДО повышайки
                      |
                    100кОм
                      |
                      +----------- GPIO4
                      |               |
                    100кОм          100нФ
                      |               |
Общая GND ------------+---------------+---- GND ESP
```

МаксимумADC≈2.1В. Резисторы желательно1%. Не подключать батарею/5В напрямую к GPIO.
Брать после защиты(BMS), не обходить её минусом делителя. Защита от переразряда
нужна аппаратная: прошивка/цвет LED её не заменяют. При выключении делитель не должен
подпитывать выключенную ESP через ADC. Это не схема для2S/другой химии/изолированной
повышайки. Обесточить перед пайкой, прозвонить общую сигнальную GND.

## Индикация

- До первой ручной FULL — прежнее отображение связи. Нет ложного заряда от floatingADC.
- После FULL в покое: зелёный при reserve>50, жёлтый21…50, красный≤20.
  Гистерезис около2–3пунктов и фильтр не дают дрожать цвету.
- У LOW/ниже — красное мигание. Неизвестное/устаревшее/отсоединённое ADC после FULL —
  фиолетовое мигание, не зелёный. После холодного старта нужен первый пакет измерений.
- Отправка navigation — прежняя белая80ms вспышка один раз, НЕ каждый retry/ACK.
  Двойное подтверждение успешной3s FIRST/LAST, identify и commissioning test сохранены.
- Обе кнопки одновременно1сек →10сек мигающего качества связи прежней палитры:
  excellentсиний/goodзелёный/marginalжёлтый/badкрасный/offlineкрасный.
  Это прежняя оценка masterhealth/RSSI/доставки, а не новый отдельный датчикRSSI.
  Во время диагностического окна навигация заблокирована; автоматический выход10сек.
  Жест, раздельное отпускание и оставшаяся зажатой кнопка не дают short/longGO.
  Для нового жеста отпустить ОБЕ кнопки. Held-at-boot не создаёт команд/жест.
  Отдельный сервисный buttonTest сохраняет старую индикацию и приоритет блокировки.

Обычный цвет батареи НЕ означает готовности принимать GO: прежние link/token/TTL
проверки работают независимо. Связь проверяется двухкнопочным жестом.

## Калибровка — только по явной команде

Страница `http://<IPпульта>/battery`, read-only status `/api/status` → `battery`.
Авторизованный POST `/api/remote/battery/calibrate?token=...&target=<MAC>&role=remote&point=full|low`.
Требуются per-boot token, реальный MACпульта, role и корректный Origin. GETне записывает.
Нельзя калибровать во времяOTA/ожиданияreboot или при зажатых кнопках.

1. Подключить делитель, поставить полностью заряженную банку, выключить зарядник,
   включить рабочий пульт, отпустить кнопки и дождаться4–5сек стабильногоADC.
2. Нажать «Запомнить FULL сейчас» (либо оператор говорит ассистенту, тот читает
   свежую телеметрию и делает один осознанный POST). Проверить fullCaptured/fullMv.
   До будущей LOW действует предварительная точка3500мВ и lowCaptured=false.
3. Работать до устойчивого снижения запаса, НЕ до выключения/браунаута повышайки.
   На выбранной стабильной точке предупреждения нажать «Запомнить LOW сейчас».
   Не калибровать по единичному морганию: оно может быть перегрузкой, контактом или
   автосном повышайки, а не разряженной батареей.
4. Сверить lowCaptured/lowMv. Записанный16B CRC-record хранится в отдельном NVS
   `remote-batt/cal-v1`, переживает перезапуск/обычнуюOTA. Старый `remote-diag/buttonTest`
   не меняется. Нет автоматического обучения min/max или записи на каждом измерении.

FULL/LOW — значения ADC*2 с реальным делителем и погрешностью, не лабораторный
вольтметр. FULLдопуск3700…4350mV, LOW3000…4150, разница≥200mV, CRC/format проверяются.
ДопускFULL4350 не разрешает заряжать обычный18650 выше4.2В. LOW не является отсечкой.
Запрос без4сек устойчивой истории/при разбросе>80mV/ошибкеNVS отклоняется, старая
калибровка остаётся. Браунаут — уже слишком поздняя и неустойчивая точка для записи.

`reservePct = clamp(100*(V-LOW)/(FULL-LOW),0,100)` — УСЛОВНЫЙ ЗАПАС ДО ПРЕДУПРЕЖДЕНИЯ,
НЕ процент оставшейся ёмкости/реальноеSOC. В JSONесть reserveIsNotStateOfCharge=true.
При неизвестном сигнале reservePct=null. Даже реальные4.0В не дают сами по себе
точногоSOC: химия, температура, ток и возраст влияют на кривую.

## Измерение / испытания / установка

ADC1/12bit/11dB, analogReadMilliVolts раз25ms, пакеты20отсчётов/0.5сек, сглаживание,
окно8пакетов(4сек), свежесть<1500ms. ADC2 с Wi-Fi не используется. Нет PWM/UART/реле.
Реальные диапазон/погрешность ADC, просадка повышайки и потребление пока НЕ измерены.

Прошли pureмодель и actualremote/nativeASan/UBSan: stable/noisy/disconnected/staleADC,
CRC/диапазоны/write-failure/reload NVS, auth/Origin, нетGETзаписи, таймерныйwrap,
1s/10s/held-release без навигации, старые кнопки/OTA/команды. Браузер проверил реальный
firmwareHTML с mockbackend на320/390/1280, ручныеPOST/error/no retry/no horizontaloverflow.
SDK ESP32S3/core3.3.11 remote собран. Sourceверсии синхронизированы0.8.4, но другие роли
ради пульта обновлять НЕ надо: R/1/protocol4/score12/партитура/банки не менялись.

Образ `build/console-remote-wifi/remote.ino.bin`, только рольremote. Не шить вmaster/slave/helmet.
Физически пульт НЕ обновлялся в ходе подготовки, STOP/GO/навигации не отправлялось.
Перед установкой проверить MAC30:30:F9:1B:FD:6C/фактическую роль/образ/новыйboot,
сохранить доступные текущие настройки и NVS/разметку на месте. Не сбрасыватьbuttonTest.
ПоHTTP fullflash/NVS backup недоступен; sourcearchive его не заменяет.
