# 0.8.6: частота12 DIM без перепрошивки — подготовлено, НЕ установлено

Включает подготовленные0.8.5 EQ/независимый голос/lockedредактор/одноразовый автостарт.
Сегодня никаких STOP/OTA/GO/изменений NVS на физических платах не выполнялось.

## Контракт

- «Приборы» → «Настроить» стандартный контроллер → «Частота PWM · DIM1–12».
- Число целое2000…25000Гц для обычной8битной сборки. Одна частота на12каналов:
  8LEDC +4MCPWM. Никаких изменений яркости, инверсии, уровней, гаммы или сцен.
- Стенд10бит: тот же диапазон;12бит:2000…9765Гц по ограничению XTAL40МГц.
  Стендовые compiledefaults сохраняются при отсутствии нового NVSключа.
- Новое значение только сохраняется; **применение после отдельного перезапуска платы**.
  Не выполняется ни автоматический reboot, ни переключение работающих таймеров.
  UI показывает действующую и сохранённую частоты, необходимость перезапуска,
  пределы платы и расчётную частоту MCPWM. Расчёт не является измерением GPIO.
- Перед сохранением нужны связь, явныйSTOP, выключенныйLIVE, разблокированный
  редактор и отсутствие выполняющейся сцены/ненулевого DIM на целевой плате.
  Сохранение само не посылаетSTOP/ALL_OFF/GO/PLAY и не публикует партитуру.
- Нельзя вводом очистить поле и случайно сохранить0; дробь/NaN/значение вне
  диапазона отвергаются, не округляются и не зажимаются автоматически.
- Для новых функций нужны master0.8.6 и0.8.6 на конкретном изменяемомslave.
  Старыеslave продолжают работать; ввод частоты для них недоступен. Не требуется
  перепрошивать остальной парк ради одинаковых номеров версий.

## Хранение/совместимость

- Независимый12B CRCrecord `stage-io/pwm-freq`: magic/version/frequency/reserved/CRC.
  Старые `pwmConfig`, `dimConfig`, реле, плеер, партитура, привязки и NVS не очищаются.
- Ошибка NVS не меняет подтверждённое savedHz. То же значение не пишет флеш повторно.
  Повреждённый record не удаляется молча: DIM блокируется с fault5 до явного
  сохранения корректного значения и отдельного reboot. Остальные NVSключи сохраняются.
- Это **аппаратная настройка NVS, не параметр сцены**. Импорт JSONпартитуры её
  автоматически не меняет. Перед обслуживанием отдельно сохранять `/api/status`
  целевогоslave с `pwmFrequency`; старыйJSONscore не заменяет backup NVS.
- Сервисная команда23, channel0, valueHz. MAC+роль+deviceBoot/session/TTL/ACK,
  явная capability из optional FQ1 extension в16reservedBytes старого64B PWM_REPORT.
  Размеры пакетов, протокол,12DIMпланы и512B STORE не меняются.
- HTTPPOST при неизвестном исходе не повторяется автоматически. Затем толькоGET
  для ACK/сохранённого значения; после потери ответа перечитать состояние вручную.
- На ESPcore3.3 ledcReadFreq() возвращает0 на duty0: в таком случае pwmHz показывает
  конфигурацию, а не ложный вывод об остановке генератора. MCPWM использует округлённый
  период80МГц, поэтому произвольное число вроде2001Гц реализуется с небольшим
  квантованием; UI отдельно показывает вычисленное80МГц/periodTicks.

## Что НЕ меняется для220В

Фазовый симисторный канал синхронизирован с сетью. Это не PWM2…25кГц:
повышать его частоту и программно сделать trailing-edge на симисторе нельзя.
Текущие Z-Cфильтр/парность полуволн/gate200мкс/STOP/защиты остаются неизменными.

Пользователь заметил подстрабливание на малой яркости. В очереди — определить,
мерцает сама220Внагрузка или низковольтные каналы от помех, и тип нагрузки
(галоген/LED). После этого можно рассмотреть отдельный opt-in минимум устойчивой
яркости/длительность gate в допустимых пределах модуля и диагностику пропусков.
Это гипотезы, не установленная причина и не обещанное исправление.
Данные модуля и допустимых входных импульсов нужны до выбора нового диапазона.
Работы с силовой частью только обесточенно; GPIO/USB не использовать для измерения сети.

## Проверки

Native ASan/UBSan: all12/default/2001Hz/reboot/polarity preservation, диапазон,
precisionbound, CRC, неактивные выходы/lease, отказ NVS, отсутствие writes/relay/
audio/reboot при сохранении. Actualmaster/slave код компилируется в firmwareмоках.
TypeScript/domain: MACbound POST, GET-only ACKpoll, STOP/lock/oldfirmware/range,
неизвестный POST/смена boot без повторов. Браузер: числовое поле/очистка/границы,
прикладное подтверждение, active≠saved без GO/scorewrites/STOP/reboot.
Физическая частота/камера/тепловой режим/помехи от220В этими тестами не измеряются.

## Завтрашняя установка

До действий проверить свежие MAC/роли/версии/boot, сохранить текущий workspace,
полные банки/working и status/NVSнастройки, согласовать сервисныйSTOP и список целей.
Новыйmaster после обычногоboot умеет включать первую сцену с выходами: удерживать
сервисныйSTOP явно на новомmaster до готовности всего парка. Никакой fleetOTA,
подачи питания на нагрузку или теста выхода автоматически при подготовке нет.
