## Проверка физических кнопок0.7.7

Remote30:30:F9:1B:FD:6C реально обновлён0.7.7 через `deploy ota remote` после
проверки MAC; новый boot/app0. **Тогда был включён безопасный buttonTest: навигация
была заблокирована даже при готовой связи.** На этом историческом этапе мастер/8slave
не менялись; позднее весь комплект обновлён0.7.8, test lock снят (см.выше).

На первом запуске без ключа NVS прошивка по умолчанию включает безопасный режим.
`/buttons` — включение/завершение, POST `/api/remote/buttons-test` требует обычные
Token/target/role и enabled=1/0. Lock сохраняется в NVS namespace remote-diag,
поэтому перезагрузка/OTA сами не разрешают сцены. Ошибка записи не меняет режим.
Завершать только явно, после безопасной проверки нагрузок; удержанная при выходе
кнопка не воспроизводится как команда.

В режиме теста: фиолетовый0x200020 — отпущены; одна нажата >=30мс — яркий белый
0x606060 всё удержание; обе — жёлтый0x606000. Работает без master. При отпускании,
если master доступен, только безопасный нулевой диагностический TX/STALE, без GO.
Identify имеет приоритет. Реальная навигация подавлена и на коротком, и на3с жесте.

API показывает raw GPIO13/14, statusPin48, forward/backRawEdges, Presses, Releases.
Постоянный probe на loopTask фиксирует переходы между HTTP-чтениями; счётчики
сбрасываются при включении/выключении теста или reboot. Полярность входа — LOW.

После записи: masterReady true, buttonTest true/buttonsEnabled false, оба входа
HIGH. При мониторинге60с:339 HTTP-ответов,0ошибок, оба rawEdges/Presses0.
Это означает отсутствие увиденных переходов; факт физического нажатия/видимости
RGB подтверждает оператор. Если оператор нажимал в этом интервале, проверить
проводку/соответствие GPIO. Сцена мастераv2/fingerprint93081004/stepnull/previewfalse
не изменилась. Ни один действительный navigation packet не послан.

Проверять напряжение GPIO относительно GND: idle≈3,3V, pressed≈0V.
10кОм — только подтяжка GPIO→3,3V; кнопка замыкает сам GPIO напрямую наGND.
Схема не должна давать резистивный делитель с промежуточным напряжением.
Если GPIO не меняется — подключение/кнопка/маркировка; если GPIO меняется, а RGB
нет — отдельно проверять физический LED/его GPIO (по фото платы, не перебирать
произвольные выходы). Счётчики — не оптический датчик.

Нативный тест actual remote.ino проверяет NVS lock/default/restore/errors,
white-held/yellow/purple, обе кнопки/debounce/wrap, только zero-ID packets,
отсутствие GO при3с и held-exit. Физические кнопки пока не подтверждены.

## Базовая архитектура и OTA0.7.6


Master у роутера хранит партитуру и ведёт единственный счётчик; remote у оператора
передаёт навигацию, slave исполняют сцены. Пульт — отдельная прошивка
`remote/remote.ino`, не режим GPIO мастера. Нет PWM, реле, аудио или filesystem.
С0.7.6 есть **только служебный HTTP/OTA**, не редактор спектакля.

## Кнопки и питание

| Пульт | GPIO | Коротко (после отпускания) | Удержание3с |
|---|---:|---|---|
| Вперёд | **13** | следующий шаг | последний |
| Назад | **14** | предыдущий шаг | первый |
| Встроенный RGB | **48** | качество / белая TX | |

INPUT_PULLUP, каждая кнопка замыкает свой GPIO наGND. Внешняя10кОм от каждого
GPIO к**3,3V** допустима вместе с внутренней. Не к5V и не последовательный
резистор в цепи кнопки. Короткие провода, для выносных — сигнал/GND витой парой.
Не путать с GPIO13=REL2 и14=DIM9 на другой плате slave; master локально1/2.

Debounce30мс. Длинное действие один раз, на отпускание дополнительного нет.
Обе кнопки одновременно отменяют жест. Boot-held/возврат связи/OTA-held не дают
фантомной команды: отпустить и нажать заново. На краях шаг ограничен.

## Сеть и индикация

WLAN **YOUR_WIFI_SSID / YOUR_WIFI_PASSWORD**,2,4ГГц, hostname `stage-remote-<suffix>.local`.
Role remote отдельной строкой в «Сети», не занимает10слотов slave и не является
назначаемым прибором. Сервис/навигация R/1 не менялись: **remote0.7.6 работает
с master0.7.2-recovery.1**. Новый score7 не требуется только ради OTA пульта.

- Синий excellent, зелёный good, жёлтый marginal, красный bad.
- Мигающий красный — нет свежего двустороннего обмена/оценка OFFLINE от мастера.
  Один цвет не различает потерю PING и потерю обратных PONG. Если свежих PING нет,
  нажатия блокируются; принятый PING при потерянных PONG может дать тот же цвет.
- Слабый белый — warmup статистики.
- **Белый80мс** — один раз при первой успешной UDP-отправке нового события,
  не на каждом retry/ACK. Это не подтверждение сцены или нагрузки.
- Белое мигание5с — identify. Оно имеет приоритет над TX-индикацией.

Heartbeat500мс сохраняется при выключенном сборе статистики. RSSI — сигнал роутера
на ESP, не прямой peer RSSI. Свежий PING для управления <=1000мс, lease3с.

## Доставка команд

Boot/session обеих плат, свежий master challenge, монотонный eventID, TTL700мс;
до4попыток0/120/240/360мс с тем жеID. Master кеширует ответ без повторного шага.
При обрыве очередь отменяется, накопленных нажатий «на потом» нет.
Пульт управляет опубликованной партитурой, не самовольно черновиком. Web preview
и опубликованный показ — контексты master, пульт не хранит своего плана/счётчика.

## HTTP/OTA0.7.6

`http://IP/` — маленькая страница обслуживания, `/api/status` — реальный JSON:
MAC/версия/bootId/uptime/IP, link readiness/PING age, сырые GPIO13/14,
счётчики навигации и отдельной диагностики, OTA-статус/slot/address.
Token выдаётся текущей загрузкой, не публиковать его в логах/скриншотах.

OTA POST `/update` требует **token + точную target MAC + role=remote** и допустимый
Origin. Пишет неактивный6MiB app-slot. ESP-образ проверяется Update, отдельно
проверяется marker `THEATRE_REMOTE_OTA_ROLE_V1` (также на границах чанков), размер
и header. Это защита от случайного образа другой роли, **не криптоподпись**.
Commit выполняется только в финальном обработчике POST, после разбора multipart.
Ошибки/abort/timeout не переносят управление в недописанный образ. Кнопки и очередь
отменяются на OTA; keepalive продолжает обслуживаться. После неудачи удержанная
кнопка не превращается в команду. NVS/storage не стираются.

Парсер/TCP находятся в worker, callbacks контроллера сериализованы через общий
ControlWebServer. Это не жёсткая real-time гарантия при записи flash.

```sh
./deploy build remote
# Первое добавление OTA к старой0.7.2 — через USB после проверки MAC:
EXPECTED_MAC=30:30:F9:1B:FD:6C ./deploy remote /dev/cu.usbmodem...
# После установки0.7.6:
EXPECTED_MAC=30:30:F9:1B:FD:6C ./deploy ota remote 192.168.50.4
```

Скрипт до OTA проверяет role/MAC/otaSupported, после — MAC/версию и **смену token**,
чтобы не принять старую ещё не перезагрузившуюся сессию за успех. Повторная OTA
тем же образом допустима. Старые пульты без загрузчика не обновляются по воздуху:
сначала USB. `helmet` пока без OTA. Не открывать update в интернет; доверенная LAN,
TLS/подписанных прошивок/master-driven fleet OTA нет.

## Проверка белого без изменения сцены

- `POST /api/remote/identify` с token/target/role — только белое мигание5с.
- `POST /api/remote/tx-test` — первая UDP-отправка зажигает белый80мс, но событие
  намеренно **eventID=0, action=NONE, token/deadline=0**. Master R/1 обязан отвергать
  его как STALE (result6), не меняя счётчик. Этот инвариант проверяется в тестах.
  Результат отдельно в diagSent/diagAcks/diagResult, не в sent/acks навигации.
- USB i/j — JSON, l — локальный белый80мс (не TX), t — такой же безопасный TX-тест.
- identify приоритетнее TX: перед проверкой80мс дождаться завершения5с identify.
- Тест реальных кнопок может переключить сцену! Только после отключения опасных
  нагрузок/согласованного безопасного шага. Сырые GPIO можно читать без команды.

В0.7.6 сохранена совместимость индикации с остальными ролями. Физическую видимость
светодиода подтверждает оператор: счётчик whitePulses — не оптический датчик.

авторизация, роли/marker/чанки/ошибки/abort/timeout/multipart ordering, отмена кнопок,
reboot, LED80мс, id0 без навигации. Общий HTTP-worker проверен отдельно. Эти тесты
не заменяют физическое радио/питание/кнопки/нагрузки. [DEPLOYMENTS.md](DEPLOYMENTS.md).
