# YX6300 — консультация, не адаптированная прошивка

Оператор сменил плеер с XY-V17B на YX6300. Просит сначала проверить питание/логику,
новую карту GPIO сообщит позже. **Код и платы не менять/не прошивать в рамках этой
консультации.** Установленная0.7.8 пока содержит команды/драйвер XY-V17B, не YX6300.
Физическая ориентация ESP подтверждена отдельно в [PINOUT.md](PINOUT.md).

## Проверенные открытые источники

1. CATALEX Serial MP3 Player manual v1.0.1,17Mar2015:
   https://raw.githubusercontent.com/MajicDesigns/MD_YX5300/main/extras/Serial%20MP3%20Player%20v1.0.1%20Manual.pdf
   - стр.2: модуль прямо назван YX5300;
   - supply3.2–5.2VDC;
   - control logic interface3.3V/5V;
   - UART TTL9600bps.
2. YX5300-24SS Datasheet V1.0, китайский документ производителя, копия:
   https://raw.githubusercontent.com/MajicDesigns/MD_YX5300/main/extras/About%20the%20Chip%20-%20YX5300/YX5300-24SS%20Datasheet%20V1.0.pdf
   - стр.5: TX pin6/RX pin7 —3.3V TTL, VDD pin4 input5V≤5.2V,
     VDDIO pin3 — **выход**3.3V, не путать с входом питания;
   - стр.18 §4.1 прямо говорит3.3V TTL serial;
   - стр.26 electrical characteristics относятся к3.3V IO;
   - это **YX5300, не найденный первичный datasheet YX6300**. Нельзя переносить
     его pin numbers/absolute maximum ratings на6300 без дополнительной проверки.
3. Библиотека MD_YX5300 прямо заявляет поддержку обоих YX5300/YX6300/Catalex:
   https://github.com/MajicDesigns/MD_YX5300
   Это свидетельство совместимости протокола типовых модулей, не паспорт IO6300.
4. Практическая схема ESP32+YX5300/YX6300 с прямым UART:
   https://randomnerdtutorials.com/esp32-yx5300-yx6300-mp3-player-arduino/
   Автор питает модуль5V, ссылается на3.2–5.2V range; RX/TX подключает к ESP32
   напрямую. Отмечены варианты ошибочной маркировки RX/TX. Это tutorial, не
   первичные electrical ratings конкретной платы оператора.

Оба PDF реально скачаны и прочитаны; локальный исследовательский cache
`/tmp/yx6300-consult/`, в Git сами чужие PDF/полные тексты не копируются.

## Что можно заключить

У типовых Catalex YX5300/YX6300 модулей3.3V-совместимое UART-управление ожидаемо,
есть рабочие опубликованные примеры ESP32. Питание модуля и уровни его UART —
разные вещи. Указание control3.3V/5V не разрешает5V на входе ESP32-S3.

Для **конкретного YX6300 оператора** строгого подтверждения TX high/максимумов
пока нет: нет фото, ссылки на товар, маркировки/схемы конкретной платы; отдельный
надёжный первичный datasheet6300 при поиске не найден. Попросить фото обеих сторон/
ссылку. При необходимости измерить TX high относительно GND отдельно от входа ESP;
DMM idle — начальная проверка, не измерение всех пиков, их проверяет осциллограф.
Если на TX5V, нужен согласователь на пути playerTX→ESPRX. Общая GND обязательна.
Не рекомендовать произвольное питание по одному названию микросхемы.

## Для следующей реализации, не выполнено сейчас

- TX ESP→RX player, RX ESP←TX player. GPIO выбираются после новой карты оператора;
  текущие17/18 остаются программно назначенными до согласованной прошивки.
- UART protocol не XY-V17B: у YX-family команда volume0x06, play-index0x03;
  старые0x13(volume)/0x07(track) не переносить. Frame/ACK/checksum и допустимые
  8/10byte варианты сверить по реальному модулю; поддержка library сама не заменяет
  стендовый тест.
- Проверить boot/init/storage select, pause/resume/stop, запросы/ACK/EOF, порядок
  файлов SD и адресацию треков, диапазон громкости и локальные fades.
- Не объявлять ACK доказательством звука. Питание/аудиовыход/нагрузку/пики UART
  проверять отдельно. Никакие UART play/volume/test команды устройствам пока
  не отправлялись в ходе этой консультации.
