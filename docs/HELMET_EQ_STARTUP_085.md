# 0.8.5 — независимый звук шлема, EQ и безопасный редактор (НЕ установлено)

Пользователь явно выбрал: при включении мастер сам запускает первую сцену с выходами,
редактор заблокирован, пульт сразу продолжает спектакль; голосовой пресет меняется
немедленно и независимо от партитуры. В ходе подготовки платы не прошивались,
STOP/GO/LIVE/параметры на действующей системе не отправлялись.

## Голос / обработка

В прежнем окне «Настройки шлема» добавлены:
-3параметрические peak-полосы30…16000Гц, gain−12…+12dB, Q0.2…8;
-отключаемые HP20…1000Гц и LP2000…20000Гц;
-полоса разборчивости: центр80…6000Гц, номинальная ширина100…6000Гц,
 мягкая сатурация0…12, параллельное подмешивание0…1.

Разборчивость берёт чистую микрофонную полосу ПОСЛЕ gate, параллельно роботизации:
это помогает сохранить согласные даже при сильном эффекте. До/после сатуратора
полосовая фильтрация; нелинейный участок2xoversampling/антиалиасLP. Это не обещание
абсолютного отсутствия цифровых артефактов. После суммирования работают выходнойEQ,
громкость и прежний peak-limiter. Новые блоки по умолчанию выключены, коэффициенты/
подмешивание сглаживаются. Точный legacy bypass при выключенных блоках проверен.
Микрофонный индикатор/реактивность света не подавлены gate/EQ. TESTосциллятор остаётся
своим диагностическим режимом; это не штатный микрофонный звук.

Усиление узкой полосы может вызвать акустическую обратную связь. Начинать с малого
подмешивания/ослабления лишнего и безопасной громкости. Испытания на реальном динамике,
разборчивость в помещении, CPU/late на аппаратуре и фактическая обратная связь пока
НЕ проверены. Нативные спектральные тесты не заменяют прослушивание/измерение.

## Независимый банк / доставка

Верхнийselect у настроек содержит только имена пресетов; работает при locked score.
Полное редактирование осталось в прежнем окне шлема в инспекторе. Несохранённая working
копия перед загрузкой другого пресета требует приложения-confirm, неwindow.confirm.
Пресеты — обычные editable, без защищённых/запертых копий.

Звук исключён из изменений сцен: новый активный банк в `workspace.helmetVoices[MAC]`,
`helmetVoiceRevision`; наmaster отдельный маленький `/helmet-voices.json` с дебаунсом
записи1.5сек. Старые `Device.voice` в draft/published НЕ удаляются/не переписываются:
это fallback при первом чтении старого JSON. После появления independent-bank именно
он авторитетен для UI/передачи звука. Копии legacy не появляются отдельными пресетами.
Backup включаетновые rootбанки; reminder/hashJSON учитывает их, fingerprint партитуры
не меняется от настройки EQ/выбора голоса. Для восстановления новых банков использовать
0.8.5: старый reader может понять партитуру, но не независимый EQ/банк.

GET `/api/console/helmet-voices`, POST с token иJSON `{mac,bank,revision}`. Конкурирующая
чужая ревизия отклоняется, устаревшие свои slider-очереди coalesce отдельно поMAC.
Неизвестный HTTPисход не воспроизводится слепо; локальная неподтверждённая копия
сохраняется вsessionStorage по возможности. Явный JSONimport передаёт отдельный
`{import:true,banks,revision}` только при unlocked; обычный workspaceautosave старую
копию независимых банков поверх них не восстанавливает.

В сеть отправляется145B lossless HelmetSound packet, отдельно от сцен. Привязка к
MAC/session/deviceBoot/revision/CRC, явныйACK. Калибровка/профиль не включает голос:
сохраняется текущий requested-enable, состояние STOP/номер сцены/лента не меняются.
Сцены по-прежнему управляют voiceOn и светом, но старый voice из cue уже не может
перетереть выбранный independent-пресет. Ранее принятый STOP не отменяется config/retry.
Наhelmet отдельный CRC/NVS-record `helmet-global/sound-v1` с2секдебаунсом; новый
профиль/EQ переживает reboot. Legacy111Bstartup-record и robot-voice bank не расширялись.
Scene512B/Cue468B/score12/P16/P17/R1 остаются прежними. LANдопускает дополнительный145B.
FirmwareReport.reserved[0]=1 у новогоhelmet обозначает поддержку globalvoice.

Для этой функции нужныmaster+helmet0.8.5 парой. Мастер ждёт ACKголоса перед первым запуском; после запуска pendingсмена пресета
НЕ блокирует переходы сцен/пульт. Старые
обычные slave/remote не надо перепрошивать. Подготовленныеremote0.8.4battery иPWM2kHz
остаются отдельными операциями:0.8.5 не устанавливает ни их, ни другойPWMпрофиль.

## Автостарт

При обычном power-on/EXT/явномsoftware-reboot master однократно вооружает запуск ПЕРВОЙ СЦЕНЫ ПОСЛЕДНЕЙ ПУБЛИКАЦИИ.
Непубликованный RAMdraft не выбирается. После panic/WDT/brownout/неизвестной причины
reset автозапуск заблокирован, требуется ручной запуск; причинаreset видна вstatus.
Это не повторение первой сцены при аварийной просадке питания. Условия: исправнаяFS/workspace, все назначенные
локальные планы загружены, свежие peerответы/ready/fault0, globalvoice подтверждён,
нетOTA/reset/maintenance. До этого `startupPending=true`, outputs не запускаются
мастером. Собственная автономная загрузка шлема — прежний отдельный контракт.

После готовности один GO step0/FIRST, Show/OFF, active/cursorValid=true. ПервоеFORWARD
пульта идёт наstep1(вторую сцену), а не запускает первую повторно. Browser для этого
не нужен. Переподключение сети, reload браузера и новая публикация не перевооружают
намерение. STOP, targetALL_OFF, serviceOTA/reset или явныйunlock до готовности
отменяют pending. После STOP ничего само не запускается до команды оператора/нового
power-on. Сбой/отсутствующий назначенный узел остаются причиной ожидания, не разрешением
тихо запустить7из8. Ранее сохранённые выходы при потере связи держатся как прежде.

ВАЖНО ПРИ БУДУЩЕЙ УСТАНОВКЕ: новая загрузкаmaster предназначена ЗАПУСКАТЬ ВЫХОДЫ
первой сцены. Для обслуживания нужно заранее согласовать это и/или отменитьpending
явнымSTOP сразу после новогоboot, до обновления/готовностиhelmet. Сейчас OTA не было.

## Блокировка редактора

После boot masterRAM `editorLocked=true`. Верхняя кнопка открывает/закрывает запись,
не останавливая текущий спектакль и не переключая сцену. Все вкладки видят один lock.
Locked: backend423 дляdraft/publish/full-workspace/preview-authoring; UI также блокирует
мышиные/клавиатурные изменения, drag, duplicate/delete/import иundo/redo. Выбор клетки
можно смотреть безLIVEGO. Управление спектаклем/STOP/пульт/независимыйголос доступны.

Одно unlock само ничего не публикует/не запускает: reconciliation только после реальной
авторской правки. Lock не переключает уже выбранный LIVE/OFF и не переигрывает сцену;
после включения по умолчанию именно Show/OFF. Для metadataJSON(version/backup) есть
отдельный маленький endpoint, не имеющий доступа кdraft/published. JSONexport/series
работают и вlocked; автоматическое напоминание оJSON не мешает lockedпоказу. Новые rootполя добавляются raw-патчем: исходные значения партитуры,
длинные double/escaping копируются дословно, иначе округление могло бы сломать её
fingerprint. На реальном приватном старомbackup384 проверено: draft/published
совпали полностью, fingerprint читается,4пресета и working вошли в independentбанк.
Это read-onlyтест старой копии, не актуальный backup действующего мастера. Обычный import требует явного подтверждения иunlocked. Это защита от
случайного редактирования, а не новая система авторизации довереннойLAN.
