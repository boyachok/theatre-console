## Карта GPIO

Нумерация **со стороны ESP**, не со стороны плеера, не порядок ножек:

| Назначение | GPIO |
|---|---|
| ESP RX ← TX YX6300 | **1** |
| ESP TX → RX YX6300 | **2** |
| REL1 / REL2 | **39 / 38** |
| DIM1–12 | **5,6,7,15,16,17,18,8,9,10,11,12** |
| WS2811 DATA | **47** |
| Встроенный статус RGB | **48**, без изменений |

GPIO1/2 — **не контакты RX/TX USB-COM** рядом с ними на разъёме. Master по-прежнему
использует локальные кнопки1/2: UART-плеер и исполнительные выходы инициализируются
только на slave, поэтому роли не смешиваются. Remote13/14 не меняется. Первые8PWM
LEDC, последние4MCPWM,25кГц; NVS уровни/инверсии сохраняются по логическим каналам,
не по прежнему GPIO. Полярность реле не менялась молча.

DATA47 оставлена для прежней **WS2811, один провод**, RMT. Слово «SPI» не означает
добавление CLK/смену протокола: для настоящей SPI-ленты нужна её модель/вторая линия.
Ориентация платы «ножками вверх, USB сверху» и физическая таблица — [PINOUT.md](PINOUT.md).

## Питание и сигналы

Общая GND ESP/player обязательна. На ESP RX GPIO1 допустимы только3.3V уровни.
Питание типовых Catalex и UART-логика — разные цепи; данные источников/ограничения
в [YX6300_RESEARCH.md](YX6300_RESEARCH.md). Фото/схема конкретного модуля оператора
ещё не получены, absolute maximum именно6300 не подтверждён. Перед прямым соединением
TX плеера→ESP подтвердить уровень, при5V поставить подходящее согласование.
Не питать усилитель/динамик от ESP GPIO. Аудио выход конкретного модуля проверить
отдельно (DAC/наушники/усилитель не равны силовому BTL-выходу).

## Реализованный драйвер

`console/yx_protocol.h`, `player.h`, семантические вызовы в actors/score_runtime:

- UART9600 8N1, **10байт**:7E FF 06 CMD feedback DATAhi DATAlo CShi CSlo EF;
  checksum=отрицательная16битная сумма байтов1–6, TX feedback=1.
- RX проверяет start/version/len/end/checksum, восстанавливает синхронизацию,
  partial frame100мс timeout. Маркеры7E/EF внутри данных не обрывают пакет.
- Эхо собственных запросов/feedback=1 не считается ответом, не создаёт ready.
  **8байт checksumless RX не предполагается**: на другом варианте модуля это будет
  видно по сырым RX/ошибкам; не выдавать поддержку семейства за универсальный паспорт.
- Команды03 play-index,06 volume0–30,09 TF=2,0D resume,0E pause,16 STOP,
 19 repeat(0=on/1=off),01/02 next/previous. EQ07 реализован по библиотеке семейства,
  но его наличие у конкретного модуля требует теста; неподдерживаемость видна NACK.
  Через старые service Op не перенесены неподдерживаемые XY-режимы0/3–7 и USB drive0:
  возвращается INVALID, а не отправляется случайный XY opcode.
- Boot: ранний STOP; выдержка~1500мс; STOP→mute0→TF select→пауза≥200мс→STOP.
  Повторный offline ALL_OFF на каждом tick не обрывает этот безопасный bootstrap;
  до его завершения resume/next/previous не принимаются.
  **Нет PLAY на старте**. Это не гарантия отсутствия аппаратного щелчка/автозвука
  самого модуля до того, как он начинает принимать UART; для этого нужна hardware mute.
- Явный play после boot разрешён и при одностороннем UART. Это не invent-ready:
  state/volume/track остаются неизвестными до настоящих ответов. Без обратного RX
  нельзя обнаружить перезапуск самого плеера; для надёжного показа нужны оба UART
  направления и отдельная аппаратная безопасность аудиотракта. Actor ACK=поставлено
  в очередь ESP, player ACK/NACK — отдельные события, не датчик слышимого звука.
- Одним атомарным admission ставятся mute0/repeat-off/play для сцены; FIFO8,
  обычный интервалTX80мс, отдельный poll timer400мс не задерживает новые команды
  на400мс. Неотправленные точки volume coalesce, **не переписывая mute перед PLAY**.
- Fade-in сцены считается от **фактической передачи PLAY в UART**, не постановки
  его в FIFO. Это не измерение момента начала декодированного звука.
- Одинаковый файл вперёд не запускается снова; back/recovery перезапускает. На
  matching TF EOF3D в single mode ставится STOP, не PLAY/next. Поздний EOF предыдущего
  файла во время queued switch не отменяет новый PLAY. В explicit repeat нет STOP
  на каждом EOF. Реальное поведение конкретной платы на границе файлов проверить!
- Непрошедший/занятый UART/ACK не ретраится слепо: у ответов нет commandID, повтор
  PLAY мог бы перезапустить трек. NACK/ошибки доступны для диагностики. Физическая
  надёжность start/EOF/паузы/фейдов ещё не проверена на модуле оператора.

## Диагностика и совместимость

Старые service Packet72B, UartStats76B и DebugPacket100B сохранены. Новый slave
по DEBUG_REQUEST reserved=1 передаёт optional ExtendedDebugPacket116B: полный10B TX,
family, playerACK/NACK/EOF и последняя ошибка. Новый master запрашивает extension
и принимает100/116B. Старому master0.7.8 по его обычному запросу возвращается100B
(prefixTX8, без family/ACK counters): неизвестные116B ему не навязываются.
Для полного стенда/страницы YX нужен master0.7.9, иначе использовать локальный
`/api/status` slave. Старый slave0.7.8 на новый запрос безопасно возвращает100B. Score7/RUN44B/STORE214B и R/1 не менялись.
В локальном status slave есть hardwareProfile, dimmerPins12, relayPins, stripPin.

После согласованной установки открыть **http://MASTER-IP/uart**, выбрать **MAC
нужного перепаянного slave**. При старой family XY тестовые PLAY-кнопки отключены,
чтобы не перепутать разводку/драйвер. При активной сцене PLAY-блок также выключен.
«Остановить ВСЕ сцены/выходы» — явная команда, приостанавливает LIVE/reconciliation
на master и отправляет ALL_OFF. Сам slave также отклоняет стендовые изменения
звука при активном local runner, даже если веб уже OFF: нужен явный ALL_OFF.
Отдельный AUDIO_STOP отменяет audio pending/ramp/queued PLAY, не даёт ему всплыть
после boot и не останавливает световую часть сцены. Это не аппаратный аварийный останов.

## Стендовый порядок на сегодня (только после разрешённой записи)

1. Уточнить MAC первой перепаянной платы; не прошивать наугад остальные старые
   разводки. Остановить master-сцену, отключить опасные нагрузки/силовой усилитель.
   При возвращении узла работающий master иначе может дать ему текущий cue.
   Если плата уже перепаяна: первое USB-подключение для прошивки делать с удержанным
   BOOT и отключёнными силовыми нагрузками, чтобы старая0.7.8 не исполнялась на новой
   разводке. OTA возможна только при безопасно отключённых нагрузках старой программы.
2. Проверить питание/общую землю/3.3V TX player/перекрёстность RX/TX; амплитуду
   и пики проверяет прибор. Подключить подходящий безопасный аудиотракт с малым gain.
3. Подготовить FAT16/FAT32 microSD (типовой модуль≤32GB), два коротких разных MP3.
   Для первого теста чистая карта и копирование файлов по очереди. Индекс — порядок
   файловой системы, числовые имена сами по себе не доказывают правильную адресацию.
4. После boot дождаться инициализации. `/uart`: проверить GPIO TX2/RX1,10байт
   исходящих кадров, реальные ACK/ответы, ошибки. При RX=0байт проверить проводку,
   питание/маркировку, не объявлять отправку доказательством работы плеера.
5. Нажать «Громкость10из30», дождаться software ACK, затем «Игратьтрек1». Проверить
   слышимый файл1, pause/resume/STOP. Сверить query43(volume),42(state),4C(track).
6. Дождаться EOF: file2 не должен самопроизвольно начинаться. На клонах проверить
   отсутствие даже короткого захода следующего трека и задержку STOP. Если есть —
   не применять на показе, зафиксировать RX и адаптировать exact hardware mode.
7. Только после этого пробовать Cue/PREVIEW fades, same-file forward и restart back.
   Стендовый браузер/нативные mocks не заменяют этот тест и реальные12PWM/нагрузки.
