# Световая задержка и повтор трека — 0.7.12 (без прошивки)

## Свет

В каждом шаге/приборе для **каждого из12DIM и отдельного «Диммер220»** добавлено
`startDelay?: number`, секунды0–3600, дробные значения. По умолчанию отсутствует=0.
Лента WS2811 не получает новый delay: её hold/stop/play семантика прежняя;
у реле уже есть отдельные задержки включения/выключения.

- Новый шаг/back/recovery начинает новое ожидание; даже если предыдущая сцена
  держала этот канал включённым, во время ожидания выход **0**.
- По окончании ожидания начинают отсчитываться **fade-in и фаза анимации**.
- Retry RUN и несвязанные LIVE-правки не откладывают deadline. Параметры канала
  можно менять во время ожидания; delay edit пересчитывается от исходного запроса.
  Если новая дата уже прошла, старт происходит сейчас, не задним числом.
- Правка delay уже работающего канала не выключает его: значение применяется
  на следующем старте. Смена яркости уже включённого канала сохраняет обычный фейд.
- Нулевая яркость, отключение модуля, смена сцены и STOP/ALL_OFF отменяют ожидание.
  После STOP дубликат прежнего RUN свет не возобновляет.
- Controls: текстовый ввод и zero-safe logarithmic fader; без spinner/изменения
  колёсиком. Вход/выход в ячейках света/аудио также переведены на эти фейдеры;
  reset «Как в шаге» возвращает null/inheritance. Старые общие поля времени шага
  отдельно не переделывались.
- Preview рисует0/◷, затем фейд; это идеальная модель, не измеренный GPIO.
  Native deadline арифметика uint32 wrap-safe, tick1мс best-effort. Отсчёт каждого
  ESP — от локального принятия cue, общего executeAt/фазового выравнивания плат нет;
  AC дополнительно квантуется парой полуволн. Это не гарантия синхронности10ESP.

## Аудио

`audio.loop?: boolean`, отсутствует=false. Галочка **«Зациклить трек»** в ячейке
звука стандартного прибора, не в helmet/voice.

- При запуске Player атомарно принимает mute → YX `REPEAT` → `PLAY_TRACK`.
  REPEAT0 включает single-track loop, REPEAT1 выключает.
- После задержки старта и actual UART TX PLAY первоначальный fade-in прежний.
  Самостоятельный повтор внутри модуля не требует нового PLAY, задержки или фейда.
- Изменение галочки у уже играющего того же файла посылает только REPEAT, без
  STOP/нового PLAY. При заполненной очереди обновление повторяется до admission.
- Для ожидающего/queued старта смена loop пересобирает транзакцию с исходным
  deadline, не продлевает delay. STOP/blank/disabled отменяют queued PLAY и loop edit.
- Обработка EOF использует **последний полностью переданный REPEAT**, не optimistic
  queue acceptance. До передачи loop-on EOF всё ещё останавливает single-track;
  mode edit не выдаётся за реально применённое состояние или подтверждённый звук.
- EOF при loop-on не порождает STOP/следующий трек/повторный PLAY от ESP. При
  loop-off прежняя single-file защита останавливает файл. Реальный модуль/носитель
  и действительность команды должны быть проверены физически.
- Уже завершённый тот же файл при forward/LIVE loop edit не перезапускается
  автоматически; back/first/recovery либо смена файла запускает по прежним правилам.

## Формат, storage, совместимость

JSON schema1 не меняется. Новые поля опциональны, старые immutable publications
не нормализуются и не получают новые fingerprint. Повтор/задержки копируются
независимо при duplicate step, скрытие модуля сохраняет данные.

**Score10, regular P/12, helmet P/13.** Cue389B, STORE/PREVIEW433B, RUN44B.
LAN433 помещается в лимит512. Старый score9 peer не считается совместимым даже
при нулевых новых опциях: сначала отдельно авторизованно обновить master и
назначенные исполнители. Remote0.7.8 остаётся совместим по R/1 и не требует OTA.

У Cue сохранён точный314B prefix score8/9; далее12×uint32 lightDelayMs,
uint8 audioLoop и26B AC. Audio startDelay остаётся в прежних3reserved байтах.
Slave cache7/8/9: проверяются magic/count/size/CRC, миграция **только в RAM**:
новые поля0/off, старый delay9 и DIM-анимации сохраняются; исходный файл не стирается.
Новый CRC считается по новому Cue. При следующей штатной загрузке плана пишется
формат10. Привязки, NVS presets/inversions, полярность реле, partitions не менялись.

Компактный JSON для master decoder:
- DIM/AC row3 = `[value,inMs,outMs]`; row4 = те же + delayMs.
- row9 = старые3 + `[mode,periodMs,phaseSeed,floor,duty,smooth]`;
  row10 = те же9 + delayMs.
- `ac` отсутствует при disabled; иначе `{enabled:1,d:[...]}`.
- audio5 — старый формат, audio6 — +delayMs,
  audio7 — +delayMs,+loop0/1. Loop-on с delay0 всё равно содержит0 на позиции5.
- Все диапазоны/типы валидируются в UI и настоящем C++ decoder, включая disabled
  данные. AC animated period минимум40мс, обычный DIM минимум20мс.

CRC migration7/8/9, millis wrap и MOCK production/local browser/mobile.
