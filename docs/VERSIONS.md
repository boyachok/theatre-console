# Общая версия и резервные копии

Название проекта: **Theatre console**. Источник версии: `version.json`.
Веб, master, slave, remote и helmet активного профиля имеют одну версию исходников
**0.7.7**: remote реально записан/OTA проверен; включён безопасный NVS-lock
для диагностики GPIO13/14/белого held. До явного завершения теста навигации нет; master/slave/helmet main не записаны.
Фактический master —0.7.2-recovery.1,8slave —0.7.2 (DEPLOYMENTS.md).
Следующая стендовая итерация — **0.7.8**; меняется независимо от того, правили
только интерфейс, только прошивку или оба. Архивные профили сохраняют старые номера.

```sh
python3 tools/release.py --set 0.7.7
python3 tools/release.py --check
```

Скрипт синхронизирует `console/release.h`, `score-ui/src/version.ts`, package/lock
и копии разделов remote/helmet.
Веб-заголовок и HTTP-версия firmware читают эти значения; сборка иCI проверяют
согласованность. Разные версии веба/мастера не выдаются за согласованное подключение:
обновить страницу и прошивку. После выпуска обновлять роли одним комплектом. У remote отдельный скетч, общий
release.h и сборка `./deploy build remote`; старый master0.7.1 не понимает пульт.
У helmet отдельный скетч и `./deploy build helmet`; для выбора этого типа в редакторе
нужен новый master. В0.7.4 score7 запускает сохранённые сцены по индексу: RUN44B,
STORE/PREVIEW214B, повтор200мс. Старые slave0.7.2/0.7.3 нужно отдельно обновить;
до готовности всех назначенных планов GO не разрешается. Service4 и навигация
remote R/1 прежние. OTA-пульт0.7.6 поэтому совместим с recovery-master0.7.2;
это не означает поддержки нового score7 старыми slave. Общий новый номер сам по себе не перепрошивает платы.

Отдельная аварийная ветка `recovery/master-072-stack` помечена
`0.7.2-recovery.1`, чтобы не выдавать исправленный образ за прежний0.7.2 и не
переводить старый комплект на новый score7 без согласования. В ней общий номер
веб/master/slave/remote тот же recovery; это не активный main0.7.7.
См.[MASTER_RECOVERY.md](MASTER_RECOVERY.md). Pre-release этой архивной ветки задан
в manifest и генерируется `python3 tools/release.py`; --set основного инструмента
по-прежнему принимает только X.Y.Z.

## Общепринятая схема SemVer

**MAJOR.MINOR.PATCH**, например1.4.2:

- **MAJOR** (1→2): несовместимые изменения публичного API/контракта.
- **MINOR** (1.4→1.5): новые обратно совместимые возможности; PATCH сбрасывается0.
- **PATCH** (1.4.2→1.4.3): обратно совместимые исправления; новые функции обычно
  относятся кMINOR, а неPATCH.
- До1.0 API считается нестабильным. В нашем экспериментальном проекте по договорённости
  используем0.7.x как номера стендовых итераций, а не обещание строгой совместимости
  любого0.7.x со всеми другими0.7.x. Перед стабильным1.0 закрепим контракт.
- Для явных предварительных выпусков можно использовать `1.0.0-beta.1`, а для
  метаданных сборки `1.0.0+<commit>`; сейчас инструмент намеренно поддерживаетX.Y.Z.

**Не путать разные счётчики:** номер опубликованной партитурыv1/v2 и номер сцены1/2
остаются отдельными. JSON schema и бинарный протокол также имеют собственные версии.
В0.7.1 scene-protocol6, cue170байт, packet214байт; старый control-protocol4/72B
сохранён для discovery/служебных сообщений. Ведомому0.7.0/0.6 для новой партитуры
нужно обновление. Старый JSON с8диммерами читается: в черновик добавляются4выключенных
модуля, неизменяемая опубликованная копия и её fingerprint не изменяются.

## GitHub

Приватный репозиторий: https://github.com/boyachok/theatre-console.
Первый commit сохраняет состояние до общей0.7.1. Каждый следующий commit — отдельная
точка возврата, релизы отмечаются тегами `v0.7.1` и т.д.

```sh
bash tools/backup.sh "Что изменилось"
# Для уже проверенного нового релиза, один раз:
git tag -a v0.7.4 -m "Theatre console 0.7.4"
git push origin v0.7.4
```

`backup.sh` проверяет приватность remote, сохраняет исходники и делаетpush.
Это явная команда, не фоновый watcher. Ключи/токены/сборки/node_modules игнорируются.
Исторические стендовые пароли WLAN находятся в исходниках/документах: не делать
репозиторий публичным без очистки истории и смены этих паролей.

Git не сохраняет изменяемые партитуры из памяти ESP сам по себе. Перед испытаниями
и правкой спектакля отдельно скачиватьJSON из веба. Снимокflash не гарантирует
работоспособность силовой нагрузки и не заменяет проверку реального стенда.
