# Камера / оптопара — отдельный slave8bit/2kHz (НЕ установлен)

Подготовлен по просьбе пользователя, стандартные образы и работающие платы остаются
на25kHz. Не новая обязательная версия флота. Параметры опционального образа0.8.3:

```sh
PWM_HZ=2000 ./deploy build slave
# Эквивалентно: PWM_BITS=8 PWM_HZ=2000 ./deploy build slave
```

Файл: `build/console-slave-wifi-pwm8-hz2000-g1.0-gray0.5/console.ino.bin`.
Меняется только частота12 DIM:8LEDC+4MCPWM.8bit, gamma1, gray0.5,0/100% постоянные
уровни. На MCPWM80MHz/40000ticks, допустимо для16bit счётчика. Опт-варианты от2kHz
принимаются CLI и C++; обычный default25kHz не менялся. UART400ms, реле, AC-ZC/gate,
лентаWS2811, сцены, инверсии и NVS/FS не меняются. Реле НЕ управляютсяPWM.

## Выбор частоты

2kHz — разумная исходная проба для медленного оптодрайвера, не обещание «без полос
на любой камере». При1/50с в выдержке40периодов, при1/100с —20; длинная выдержка
лучше усредняет PWM. Rolling shutter, короткие/HDR-подэкспозиции и автоматика телефона
могут показать полосы. Проверять именно целевой телефон/режим при реальной яркости.
Если драйвер подтверждённо выдерживает,4/8kHz могут быть следующим компромиссом для
камеры.25kHz обычно лучше по усреднению камерой, но может быть слишком много для
конкретной оптопары/затворной цепи. На2kHz возможен слышимый писк компонентов.

Дефект2.5Hz, обнаруженный ранее, НЕ был несущей PWM: ритм следовал UART400/1300ms.
Пользователь нашёл отсутствие нормальной общей земли ESP–плеер. Это отдельная проблема,
смена25kHz→2kHz сама по себе не чинит UART/землю.

## Оптопара / MOSFET

Нужны текстовые маркировки, схема затворного драйвера и ток нагрузки, а не фото.
Медленная фототранзисторная оптопара может искажать короткие импульсы. На2kHz/8bit
минимальный ненулевой импульс около2us; отсутствие потерь/нормальную нижнюю яркость
нельзя вывести из факта компиляции. Скорость зависит от тока, насыщения, резисторов
и ёмкости затвора. Снижение частоты уменьшает количество переключений, но не исправляет
недостаточное Vgs/отсутствие драйвера. Смотреть Rds(on) при рабочемVgs, не только Vgs(th).
Нагрев на100% может быть проводниковым и почти не зависит от частоты.

Пробовать сначала1низковольтный канал с небольшой нагрузкой и безопасным контролем
температуры при1/5/10/25/50/75/100%. Не испытывать силовую сеть через ESP/USB.
Камера/электрическая форма/нагрев пока физически не проверены. Нет автоматических
STOP/OTA/GO или правок партитуры в ходе подготовки. Установку согласовать отдельно,
свежие JSON/настройки/bank backup и MAC/role/slot/newboot обязательны.

## Проверки

Полный nativeASan/UBSan прошёл, новый2kHzтест проверяет программные уровни всех12каналов,
OFF/full/малые уровни, линейную кривую/инверсию иSTOP через mockHAL. Частоты mocks
берутся из реального профиля, не захардкожены25kHz. SDK ESP32S3/core3.3.11 сборка прошла.
Это не осциллограмма и не испытание камеры/силового каскада.
