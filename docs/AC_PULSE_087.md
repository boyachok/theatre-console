# 0.8.7: пробный импульс открытия симистора — подготовлено, НЕ установлено

Пользователь уточнил:4 галогенные лампы по20Вт на линии (80Вт), напрямую220В,
без трансформатора; при30% подстрабливают, после50% лучше, на полном не мерцают.
500Вт галоген ведёт себя лучше. Разница может быть тепловой инерцией нити,
неустойчивым открытием/удержанием симистора или иной электрической причиной.
Ни одна из этих причин пока не доказана. Это эксперимент, НЕ объявленный flicker-fix.

## Что добавлено

- «Приборы» → «Настроить» обычныйslave → «Диммер220 · пробный импульс открытия».
- Число200…400мкс, исходные200мкс. Разрешено менять только приSTOP/LIVEoff,
  unlockedредакторе, свежем подтверждённом slave и нулевыхrequested/pairedAC.
- Отдельное прикладное подтверждение; ни STOP, ниGO/PLAY/reboot не отправляются.
  Значение сохраняется и применяется к будущим импульсам сразу вSTOP, без reboot.
  Сам свет не включается. «Ввести исходные200мкс» только заполняет поле: нужна
  отдельная кнопка сохранения. «Отмена» окна приборов не откатывает уже сохранённое.
- Обычная200мкс конфигурация сохраняет прежнюю фазовую таблицу, задержки и RMTкадр.
  Нет изменения частоты сети, крутизны силового фронта, trailing-edge или пачек
  импульсов. Низковольтные12DIM и их настройка2000…25000Гц независимы.
- Фильтр Z-C/6интервалов/парность/CPUwatchdog/потеря синхронизации/LOWEOT сохраняются.
  Ни потеря сети, ни запись настройки не сбрасывают STOP или индекс сцены.
- Slave→master добавлен необязательный64B AC_REPORT(type23) сsession/boot/sequence,
  длительностью и счётчиками. Старые прошивки совместимы, поле для них недоступно.
  Команда24/channel0/valueµs, MAC+token+TTL+ACK. Неизвестный HTTPPOST не повторяется.
- В UI во время работы доступны чтениеrequested/paired/qualified/halfUs и накопленные
  goodZero/scheduled/late/skippedPulses/syncLosses. Это **программные счётчики**, не
  измерение тока лампы, напряжения, формы gate или температуры.

## Временная граница

Каждый Pulse содержит собственную длительность и epoch. Смена настройки вSTOP
инвалидирует старыйPulse; worker не подставляет новую длительность в старый кадр.

Прежний максимум fire = halfUs−1000 при200мкс. Теперь:
`latestFire = halfUs −800 −pulseUs`.
HIGH оставляет прежние300мкс до конца допустимого окна (150мкс late +150мкс submit),
конец окна по-прежнему halfUs−500; поздние кадры пропускаются, не догоняются.
При400мкс самая поздняя фаза сдвигается раньше на200мкс: **нижний предел яркости
может немного подняться**. Значения сцен не переписываются;0 остаётсяOFF. При30%
этот крайний ограничитель не должен участвовать. Это не универсальная коррекция гаммы.

## NVS/безопасность

Независимый12B CRCrecord `stage-ac/pulse-v1`, debouncing не нужен: запись только
явной кнопкой, не вISR/каждой полуволне/кадре. Повтор того же значения не пишет NVS.
Отказ записи оставляет прежнее значение. Ошибка открытия NVS/CRC блокирует именноAC
сconfigFault до явного корректного сохранения/восстановления; новыйGO нужен отдельно.
Старые ключи, уровни/инверсии/реле/плеер, партитура и полные банки/working не удаляются.
Настройка аппаратная, не сцена: JSONscore её автоматически не восстанавливает.
Сохранять отдельныйstatus целевой платы перед обслуживанием; HTTP не даёт fullNVSдамп.

Дополнительно закрыто окно гонкиSTOP: нулевойlevel/stop сериализованы тем жеio-mutex,
что иauthorize→matrix-map→RMT-submit. После возвратаSTOP уже авторизованныйworker
не может заново подключить gate. Двухпоточныйhostтест без этой сериализации падает,
с ней проходит. Уже открытый симистор при этом закрывается при нуле тока, не
мгновенно по softwareSTOP;STOPне заменяет физическое отключение сети для работ.
**Это не установленная причина мерцания на30% и не осциллограмма.**

Диапазон200…400 — предел реализованного программного эксперимента, НЕ паспортная
сертификация неизвестного модуля. До физического выбора300/400 проверить допустимые
входные импульсы/ток и назначениеPSM по данным модуля. УвеличениеHIGH увеличивает
нагрузку управляющей части. Не добавлять нагрузочные резисторы/конденсаторы наугад.
Любые силовые/монтажные работы только обесточенно; не измерять сетьESP/USB.

  повторов; productionMOCK UI/confirm/default200/clearable/200…400/320/375/390,

## План испытания после отдельно согласованной установки

1. Свежие MAC/роль/образ/boot, самая новая партитура/банки/working/status, согласованный
   STOP и конкретныйslave с4×20Вт. Новыйmaster умеет автостарт первой сцены: не давать
   всему назначенному набору статьready до явного сервисногоSTOP на новомmaster.
2. База200мкс: оператор вручную задаёт фиксированные10/30/50/100%, фиксирует
   визуальный результат/выдержку и дельты счётчиков. Автоэкспозицию камеры не смешивать
   с эффектом изменения импульса; учитывать и самую короткую рабочую выдержку.
3. Только при допустимости для модуля:STOP→300мкс→отдельный ручнойпуск той же сцены,
   затем при необходимостиSTOP→400мкс→тот же пуск. Остальные параметры не менять.
4. Если нет воспроизводимой пользы, пропуски/нагрев/поведение хуже — вернуть200мкс.
   Не выдавать более длинный импульс за устранение100Гц температурной пульсации нити.
