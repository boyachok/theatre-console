# Задержка старта трека —0.7.11 (подготовлено, НЕ прошито)

Ячейка **«Звук» конкретного прибора в конкретном шаге → «Задержка старта трека»**,
секунды0–3600, дробные значения допустимы (1.25с →1250мс). Текстовое поле без
spinner/wheel-adjust и логарифмический фейдер с настоящим нулём. Для helmet/голоса
контрол не предлагается. Поле JSON `audio.startDelay` опциональное; отсутствие=0.
Старые сцены/копии/неизменяемые публикации не переписываются ради нового default.

## Семантика

- При новом запуске файла, back/first/recovery slave начинает отсчёт от принятия
  сцены. Старый файл останавливается; новый PLAY не ставится в очередь до deadline.
- **Фейд начинается с фактического TX PLAY**, не со старта сцены/таймера/FIFO admission.
  Явная задержка — минимум перед запуском UART-транзакции; дополнительно требуются
  STOP/mute/repeat/play, свободная очередь, boot init и декодированиеSD. Это не
  обещание точного слышимого начала до миллисекунды/синхронного звука разных ESP.
- Если тот же трек уже играет, forward продолжает его без STOP и новой задержки.
  После EOF forward того же файла также не выдумывает повторный запуск.
- Если тот же файл ещё **ожидает** старта и пришла другая сцена, предыдущий таймер
  заменяется задержкой новой сцены. Другая сцена с пустым треком/disabled audio
  полностью отменяет старый pending/queued PLAY, даже при ненулевом fade-out.
- Повторы RUN200мс и LIVE-правки света/громкости не откладывают deadline заново.
  LIVE-правка самой задержки до PLAY пересчитывает её от исходного принятия сцены;
  если срок уже прошёл — запуск возможен сейчас, не ретроспективно. Правка delay у
  уже играющего файла не прерывает звук; новое значение применяется при следующем старте.
- AUDIO_STOP/ALL_OFF/обновление/стоп программы отменяют timer и ещё не переданный
  PLAY. Старая повторная посылка не оживляет STOP; новый явный GO разрешён.
- **Предпросмотр OFF не STOP**: правки только сохраняются, но ранее принятый локальный
  таймер, как фейд/задержка реле, может продолжиться. Для отмены нажать STOP/ALL_OFF.
- Веб-модель показывает «ожидание»,track=null/volume0 до due, а не выдуманное playing.
  Она не измеряет UART/слышимый звук; actual firmware подтверждает PLAY по своему TX.

## Хранение/совместимость

Компилятор оставляет старый audio array5 для нулевой задержки; при ненулевой —
`[track,volume,enabled,fadeInMs,fadeOutMs,startDelayMs]`. Backend строго проверяет
целые миллисекунды0–3600000, атомарность/CRC/запись планов прежние.

**Score9, capabilityP/10 regular иP/11 helmet**. Задержка хранится в прежних3байтах
Cue.reserved (24бит little-endian), так что Cue314/STORE358/RUN44/LAN512 не растут.
Нужны **master и назначенные slave0.7.11**: score8 firmware проигнорировала бы новый
таймер, поэтому она не объявляется ready. Пульт R/1 не требует обновления.

Старые cache format0(score7/170B) и8(score8/314B) проверяются по размеру/CRC,
старые reserved bytes обнуляются в RAM. Анимации/яркость/фейды сохраняются, delay=0.
Файлы не стираются/не переписываются при boot; новый STORE создаёт format9 через
временный файл/rename. Master читает старые a5 без изменения workspace/публикации.
GPIO/плеерный протокол/партитура/настройки NVS не переназначены/не сброшены.
