# Предпросмотр и пульт — 0.7.8 (подготовлено, НЕ установлено)

## Почему перехода сейчас не было видно

В реально установленном remote0.7.7 был включён оставленный нами buttonTest:
пакеты только диагностические id0/STALE, navigationTX0 и master stepnull. Поэтому
реального перехода, который мог бы отобразить веб, не происходило — это не
доказательство потери UDP. В recovery-вебе уже есть follow активного опубликованного
шага, но инспектор/выделение редактора отдельные; новое LIVE-follow объединяет их
и добавляет навигацию draft bank на master. Не выдавать это за найденную поломку
всей прежней подписки status.

## Что просил оператор

Один переключатель **«Предпросмотр»**, один авторитетный счётчик на master и пульт
через master в обоих режимах. Не переносить счётчик в браузер/пульт и не посылать
remote→slave значения напрямую. На3с FIRST/LAST — отдельная подтверждающая индикация.

## Включён: LIVE-черновик

Включение — явное разрешение исполнения выбранной сцены/её правок! Страница
начинает с фактического режима master; после reboot master LIVE выключен и нет
автозапуска. Браузер компилирует и передаёт master полный draft bank всех шагов
назначенных приборов, а не только одну показанную строку. Он живёт в RAM master.
Workspace с исходным черновиком отдельно сохраняется штатно; RAM-план до публикации
не объявляется сохранённым во flash slave.

- Выбор сцены в вебе меняет master cursor через guarded draft-go. Правки текущего
  cue автоматически передаются master (coalescing~100мс) и получают новую transition.
- Правки другого шага обновляют банк, но не переключают текущую сцену.
- Пульт навигирует тот же банк без участия браузера. После закрытия браузера
  последняя принятая RAM-версия остаётся доступна, пока master не перезагружен.
- Browser polling следует stepId/navigation master; в LIVE выделение/инспектор
  тоже переходят на выбранную пультом сцену. Параметрическое обновление transition
  не переопределяет человеческое выделение как новое движение пульта.
- Устаревший web intent с прежним navigation epoch получает409, не перетирает
  более поздний выбор remote. Master-follow не отправляет обратный GO (нет echo loop).
- PREVIEW214B содержит текущий cue, независимо от опубликованного плана; повтор200мс.
  Получатели — **назначенные MAC проекта**, не все найденные контроллеры сети.

Изменения структуры/привязок передаются полным снимком. Обычные правки — маленькие
patches changed device/step/cue. Проверяются base fingerprint **и монотонная RAM
revision**, поэтому ABA/replay не применяются. Patch валидируется на копии, commit
атомарный; изменённые CRC пересчитываются. Удаление активной MAC в LIVE отклоняется:
сначала выключить предпросмотр перед перепривязкой. Непринятый draft не двигает cursor.

## Выключен: синхронизация памяти

OFF сначала приостанавливает LIVE на master, **до компиляции/публикации**. Даже
ошибка в новом cue не оставляет случайно включённый live-edit. Ожидаемый fingerprint
блокирует запуск несинхронизированного/невалидного черновика до исправления.

При изменении проекта (coalescing~350мс) веб автоматически создаёт следующую
неизменяемую публикацию и передаёт master; тот доставляет планы во flash назначенных
контроллеров. Ручная кнопка публикации на ESP больше не нужна. Повторные неизменённые
снимки не создают лишних версий. Во время длительной записи нет обещания жёсткого RT.

- **Синхронизация не запускает новую сцену** и не откладывает скрытый GO на потом.
  После readiness нужен новый явный remote/web action.
- Счётчик сохраняет логический stepId, в том числе при переупорядочивании. Если шаг
  удалён, индекс ограничивается новым диапазоном, UI не получает второй счётчик.
- До ACK версии/CRC всех назначенных планов новый GO отклоняется. Показано «Память N/M».
  Отклонённый remote event не исполнится после завершения загрузки сам по себе.
- RUN44B использует локальный индекс/версию/CRC, нет fallback на старый full-cue RUN.
- Уже принятый slave program/фейды продолжаются. OFF — не blackout/STOP/аварийный
  останов; также не отключает автоматически ранее снятую привязку контроллера.
  Перед перепривязкой ответственно выключить его нагрузки/сцену штатным способом.

На ESP run-active и cursor-valid разделены: опубликованный план может грузиться,
счётчик сохраняться, а новый RUN ещё не запущен. Веб не рисует запрос как принятый
переход до статуса master. ACK slave не фабрикуется из HTTP200/UDPsend/публикации.

## Пульт и удержание

GPIO13/14 INPUT_PULLUP и внешние10кОм к3,3V; кнопки напрямую наGND. Коротко — действие
на отпускание. GPIO13 удержание3с LAST; GPIO14 удержание3с FIRST. Дополнительного
шага на отпускание после3с нет.

- Белый80мс — первоначальная UDP-отправка, не гарантия приёма.
- **Два ярких белых по120мс с промежутком120мс** — только после совпавшего ACK APPLIED
  для FIRST/LAST. Первый начинается через120мс после ACK. Повтор/чужой/отрицательный
  ACK не увеличивает longConfirmations и не подтверждает переход.
- Это подтверждение **принятого master перехода/выбора края**, а не завершения фейдов
  или датчика нагрузки. Если уже на краю, counter остаётся там, ACK всё равно допустим.
- Безопасный buttonTest0.7.7 — другой режим: purple idle/white held/yellow both,
  навигация запрещена. Его persistent NVS-lock надо **явно** завершить перед реальным
  показом, не автоматически при OTA. На момент подготовки0.7.8 lock ещё включён.

## API/состояние

Новые draft/preview-mode/draft-go защищены token, navigation guard/deadline для
выбора; RAM-обновления — base/revision. OFF не требует прежнего navigation epoch,
так как сохраняет реальный cursor и лишь прекращает LIVE. Общий HTTP-worker
сериализует callbacks на controller, сокетные ожидания отдельно.

Status console: step/stepId, navigation, transition, livePreview, running, syncing,
draftFingerprint/draftRevision/syncFingerprint, ready/storedDevices/plannedDevices.
Обратная совместимость explicit single-cue `/preview` сохранена как отдельный
legacy-инструмент; новый переключатель его не использует.

## Проверка и установка

Нативные ASan/UBSan: actual MasterStore full/patch/atomic rejection/ABA/reorder/
OFF-invalid/no delayed GO, actual remote master dispatch draft vs publication,
actual scheduler214B draft[index] vs44B RUN и preload, remote.ino double long ACK,
прочие жесты/OTA/persistent test lock. Доменные тесты — compiler delta/transport
mode/replay/epoch/OFF on invalid. Production browser на MOCK HTTP проверяет LIVE
правки без публикации, remote→counter→инспектор без echo, OFF авто-синхронизацию
без GO, readiness/ACK distinction, helmet/remote binding, mobile320/375/390.
