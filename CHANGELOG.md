# Изменения Theatre console

## 0.7.4 — локальный запуск по номеру, общий счётчик master (НЕ прошита)

- Счётчик остаётся только у master; пульт навигацией и веб-GO управляют им же.
  Slave/helmet исполняют сохранённый cue по step/version/CRC, без значений в RUN.
- Score protocol7: RUN44B вместо214B, STORE и явный draft-PREVIEW214B;
  повтор активной сцены200мс, UI-пауза опроса200мс. Первая отправка сразу по слоту.
- До ACK версии/CRC каждого назначенного плана GO блокируется, отвергнутое событие
  позже не исполняется само. Нет плана/не совпала версия — NOT_READY и докачка;
  старый full-cue RUN не используется как fallback. Файл/структура cue прежние.
- Реальная «Сеть»: версия, текущий подтверждённый шаг, ответы сцен отдельно от ping,
  ожидание ACK/применена/ошибка/загрузка. HTTP200 не создаёт подтверждение.
  Защита от старых run/seq/boot/отрицательных ACK и idle-подтверждений чужой сцены.
- Явные «Пропись / Показ»; показ использует immutable published, черновик исполняется
  только отдельным preview. События master синхронизируют активный шаг интерфейса.
- Новые capability P/6/P/7; для нового запуска нужно обновить master и назначенные
  slave/helmet. GPIO/NVS не менялись, фактически записанные0.7.2 не трогались.
- Native ASan/UBSan: настоящий scheduler/handlers,10узлов/200мс/90мс span рассылки,
  lookup из flash, CRC/пропуски/дубликаты/STOP/preview/готовность/ACK. Это симуляция,
  не RF-замер10плат.28domain, browser local/ESP-MOCK, все4бинарника собраны.
  Программный ACK не означает завершение фейда или измерение лампы/динамика.

## 0.7.3 — helmet (подготовлена, НЕ записана)

- Четвёртая отдельная прошивка helmet: ESP32-S3 N16R8, WS2811 GPIO47, RGB48;
  безPWM/реле/UART-плеера/HTTP/OTA. Настраиваемые1–1024точки, те же эффекты/RMT.
- Профиль Helmet в редакторе: только LED/VOICE, без номера трека; bool-запрос
  голоса и явно отсутствующий DSP/ADC/DAC backend, без фиктивного «звук играет».
- Общий SlaveStore/безопасный mountFS, сохранение CRC/atomic rename, handshake,
  ACK/дубликаты/обрыв и автономная анимация. Capability P/5 в прежнемHELLO72B.
- Проверка типа MAC-привязки, старые JSON/immutable publication сохранены.
  Protocol4/score6/размеры и схема/интервалы рассылки RUN/STORE не менялись.
- Исправлено описание архитектуры: планы действительно сохраняются в slave flash,
  но RUN пока содержит полный cue, локальный запуск только по номеру не завершён.
  Прямой remote→slave рассылки нет; навигация идёт через master и видна браузеру.
- Все4бинарника собраны; ASan/UBSan, domain/browser и CI отдельно от физического
  испытания, которого ещё не было. Ранее записанные0.7.2 не перепрошивались.
  См.docs/HELMET.md и docs/SCENE_DELIVERY.md.

## 0.7.2 — отдельный remote и собственные подтверждения

- Третий отдельный бинарник remote: кнопки13/14, INPUT_PULLUP + внешние10кОм к3,3V,
  short/3s, общийRGB48-статус, белая TX-вспышка80мс один раз на событие.
- Та жеWLAN; отдельное обнаружение remote, реальные ping/RSSI/ACK/таймауты в «Сети»,
  идентификация. Не занимает10слотов slave, не выбирается прибором, не имеет нагрузок/веба.
- Boot/session + challenge +700мс срок, повторы с тем жеID без повторного перехода;
  отмена очереди/жестов при обрыве, без фантомного нажатия при старте/возврате связи.
- Master физические кнопки и remote используют одну навигацию опубликованной партитуры.
- Вместо window.confirm — собственные диалоги. Для удаления сцены можно отключить
  вопрос до reload; блокировка браузерных окон localhost больше не мешает редактору.
- Общая версия веб/master/slave/remote0.7.2, три сборки; source/native/browser проверки
  отдельно от ещё необходимого физического испытания. Запись на платы не выполнялась.

## 0.6.0 — ON/OFF матрица, presets/инверсия, отзывчивость

- Убран alias «Диммер PWM». Матрица и главное управление переключают PWM поканально; яркости только в настройках.
- Ведомый хранит яркость включения (default255, явный0 допустим) и инверсию каждого из8 каналов в NVS. GPIO/25кГц прежние.
- Сохранение настроек не вызывает ALL_OFF/STOP, сохраняет другие выходы и логический ON/OFF. Полярность реле 0.6 также не сбрасывает PWM/плеер. Нулевой старт/lease сохраняются.
- Старые ведомые совместимы по обычному PWM255/0; новые настройки требуют обновления. На старых запрещён конфиг реле с активными выходами, чтобы DISARM не сбрасывал нагрузку.
- HTTP-задача отдельно от controller loop, callbacks сериализованы очередью, ответы отложены до HTTP-задачи. Убраны пауза120мс и секундный опрос при ACK.
- HTTP deadline/client+seq, защита от поздних/переставленных запросов, ограничение старой подготовки. HTTP/ACK и loopGapMaxMs в диагностике.
- Protocol4/72 сохранён, добавлены op21/22 и PwmReport64. Legacy3/64 и debug100 поддержаны.
- Host/threaded HTTP и мобильные UI-тесты пройдены, 3-секундный HTTP отвергается в тесте. Обе роли собраны.
- Мастер A0:85:E3:E2:BC:D4 записан 0.6, Wi-Fi/IP подтверждены. Ведомые на момент проверки не отвечали; новая ведомая прошивка и фактический телефонный отклик на железе ещё не проверены.

## 0.5.1 — PWM 25 кГц / настройка реле

- Восемь LEDC: 25 кГц, прежние 8 бит / 0–255, явный XTAL 40 МГц; ошибка настройки clock не разрешает ненулевые PWM.
