# Консоль: тестовая прошивка 0.7.0 / интерфейс 0.3.0

Подготовлена отдельная пара master/slave в `console/`. Сборка и автоматические
проверки не заменяют проверку на платах. В этой итерации USB/OTA-записи не выполнялись.
`control/` 0.6.0 сохранён без изменений; установленный ранее мастер остаётся на нём
до отдельной записи. Старые ведомые 0.4.x обнаруживаются, но партитуру не исполняют:
для назначенных контроллеров нужна новая ведомая прошивка.

## Сборка и запись

```sh
cd /Users/boyacheek/Projects/theatre-esp32
./deploy build master
./deploy build slave
# После проверки MAC подключённой платы:
./deploy master /dev/cu.usbmodemXXXX
./deploy slave /dev/cu.usbmodemXXXX
```

Профиль `console` теперь выбран по умолчанию. ArduinoJson 7.4.3, ESP32 core 3.3.11,
PSRAM OPI 8 MB / flash 16 MB. React собирается в режиме ESP и gzip-ресурсами
включается в приложение: отдельной записи файловой системы для веб-страницы нет.
Приложения: `build/console-master-wifi/console.ino.bin` и
`build/console-slave-wifi/console.ino.bin`. Для OTA допустим только этот app `.bin`,
не merged/bootloader/partitions. Размер OTA-слота — 6 MiB.

Сеть остаётся `YOUR_WIFI_SSID` / `YOUR_WIFI_PASSWORD` (2.4 GHz, внешний роутер). После записи открыть
`http://<IP мастера>/`. Последний известный IP прежнего мастера — `192.168.50.119`;
DHCP может выдать другой. Адрес/MAC смотреть в Serial115200 (`i` / `j`) или роутере.
Установленный ранее мастер: `A0:85:E3:E2:BC:D4`. Имя устройства и настройки
выходов не следует сбрасывать при обычной записи. Порт USB не является идентичностью.

## Первое испытание

1. Сначала мастер и **один** ведомый, без силовой/сетевой нагрузки. Сверить MAC до
   записи; не записывать master/slave по случайному первому USB-порту.
2. «Сеть»: найти ведомый и нажать лампочку в его строке — RGB GPIO48 мигает белым 5с.
   Отдельная лампочка вверху идентифицирует мастер.
3. «Приборы» → настройки строки → «Контроллер»: назначить обнаруженную MAC. IP
   подставляется из реальных отчётов, не является идентичностью. Для остальных
   неназначенных приборов оставить нулевые выходы/пустой звук.
4. Задать DIM1, например 100%, вход 0.2с; скопировать шаг и поставить 0%, выход 1с.
   Клик по нулевой ячейке сразу ставит **целевое значение**100%, но редактирование
   само по себе не запускает нагрузку. Запуск — кнопками/списком в шапке. Изменённый
   уже текущий шаг можно явно применить повторным нажатием плеера.
5. «Опубликовать»: неизменяемая версия сохраняется на мастере и передаётся только
   назначенным MAC. В «Сети» дождаться этой **версии** у ведомого; затем проверить
   подтверждённый **шаг** при переключении. Публикация сама не запускает сцену и
   не выключает исполняемые выходы.
6. Кнопки веб-плеера испытывают текущий черновик; физические кнопки работают с
   последней опубликованной партитурой. Не редактировать её одновременно из двух
   браузеров: совместное редактирование/слияние изменений не реализовано.
7. Проверить фейд при прерывании новым шагом; отдельно отключить роутер во время
   фейда. Ведомый должен закончить переход и удерживать состояние. После возврата
   связи — согласование текущего шага, аудио запускается с fade-in.

Проверка UART настоящим XY-V17B всё ещё обязательна: успешный пакет сцены не доказывает
проигрывание файла. Веб-визуализация не является измерением физического выхода.

## GPIO

| Функция | GPIO |
|---|---|
| DIM1–8, 25 кГц, 8 бит | 4, 5, 6, 7, 9, 10, 11, 12 |
| REL1 | 8 |
| REL2, новый | 13 |
| ESP TX → плеер RX / ESP RX ← плеер TX | 17 / 18 |
| RGB-индикатор | 48 |
| Кнопка вперёд / назад, замыкание на GND | 1 / 2 |

Кнопки используют внутренние pull-up: короткое — шаг, удержание3с — последний/первый,
без дополнительного шага при отпускании. Дисплей не требуется.

Для включения реле выбрать правильную полярность в настройках REL1/REL2: HIGH или
LOW включает. При неизвестной полярности новый выход оставлен входом; отправка
включённого реле без выбранной полярности запрещена компилятором партитуры. Полярность
хранится в NVS ведомого. Нужны аппаратные неактивные подтяжки, подходящие драйверы и
общая сигнальная земля. ESP GPIO — 3.3V; это не схема безопасной коммутации 230V.

**Лента пока не подключена к выходам прошивки.** Редактор эффектов работает локально,
но команда `play` для ленты отклоняется, а не подтверждается как исполненная.
Нужно уточнить модель: WS2812/SK6812 (DATA) или SPI DATA+CLOCK, питание и GPIO.

## Обмен и сохранение

- MAC-адресация, UDP4210 через роутер, отдельные идентичности загрузки master/slave.
  Кадр сцены172байта, параметры прибора128байт; максимум512 шагов в wire-формате.
- Версия + CRC32 для поэтапной передачи/сохранения части партитуры ведомого.
  Файлы сохраняются во flash, но сам старт после питания остаётся нулевым.
- Абсолютная текущая сцена: сразу после явного перехода и согласование примерно
  каждые500мс. Новые переходы монотонны; повторы не перезапускают фейды/трек.
- Линейные фейды на ведомом, задержки реле заменяются новым шагом. Один и тот же
  трек вперёд не перезапускается/не зацикливается после EOF; назад — запуск заново;
  пустой трек — fade-out/STOP. UART имеет аппаратно обусловленную дискретность.
- **Изменение относительно 0.6:** при потере связи уже запущенная локальная сцена
  продолжает исполняться, затем удерживается. Нет автоматического ALL_OFF/STOP.
  Это не аварийный останов. Старые прошивки сохраняют старый failsafe, их нельзя
  считать эквивалентными. Потеря питания самого ведомого всё ещё даёт нулевой старт.
- После перезагрузки мастера партитура сохраняется, но текущий запуск автоматически
  не восстанавливается: нужен явный запуск. Ведомые до него могут держать старую сцену.
- Журнал двух файлов на мастере: workspace и компактная публикация без дублирования
  workspace. Подтверждённая запись восстанавливается при сбое между rename.
  Пустой storage автоматически форматируется один раз; непустой повреждённый раздел
  автоматически **не стирается**. Лимит workspace1.5MB, publish2.5MB; штатные100×10
  помещаются, произвольные512×10 могут превысить размер хранилища/JSON.
- Сброс сети забывает реестр/имена и повторяет поиск, но не стирает WLAN, партитуру,
  привязки MAC или настройки выходов, не посылает ALL_OFF. Новый сеанс связи может
  заново согласовать сцену и перезапустить её аудио с fade-in.

## Сетевая диагностика

RTT/p95 и TX/RX/ACK/таймауты относятся к диагностическим PROBE/ECHO. RTT на экране —
медиана текущего окна. График добавляет реальные новые ответы/таймауты, не имитирует
пинг при опросе HTTP. «Тест» выключает дополнительные измерения, не обязательные
согласования сцены/загрузку партитуры. Подтверждённый шаг/версия приходят отдельно
из SCORE_ACK. Это знание сцены контроллером, не датчик нагрузки.

RSSI — сигнал роутера на ESP, не прямой сигнал master↔slave. RGB: синий — отлично,
зелёный — хорошо, жёлтый — нестабильно, красный — плохо, мигающий красный — нет связи,
медленный слабый белый — накопление статистики. При выключенном тесте цвет учитывает
RSSI и свежесть обязательных ответов, а не выдуманную статистику потерь.

Доступ только из доверенной изолированной LAN: публичный per-boot токен не является
паролем пользователя, криптографической аутентификации UDP/подписанных обновлений нет.
Обновлять платы без подключённой опасной нагрузки; восстановление связи с работающим
мастером может вновь применить текущую сцену.
