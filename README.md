# Theatre console

Театральная система управления светом и звуком на ESP32-S3.
Партитура редактируется в браузере, сцены переключаются с сайта или отдельного пульта.
Система работает в локальной Wi-Fi-сети без облака и подключения к интернету.

## Возможности

- **Партитура спектакля:** сцены, каналы приборов, групповые правки и перетаскивание строк.
- **Свет и звук:** диммирование, реле, фонограммы, адресные ленты, плавные переходы,
  задержки и циклические эффекты.
- **Два режима редактирования:** без применения правок к выходам или с применением
  правок работающей сцены в режиме «Предпросмотр» (LIVE).
- **Управление показом:** переходы вперёд/назад и к первой/последней сцене.
- **Голосовой шлем:** локальная обработка микрофона, редактируемые пресеты и эквалайзер.
  Выбор звука не требует смены сцены; сцены отдельно управляют включением голоса и светом.
- **Сохранение:** черновик и опубликованная партитура, автосохранение, импорт и экспорт JSON.
- **Защита от случайной правки:** блокировка редактора; в новом интерфейсе — отдельное
  подтверждение входа в партитуру. Выбор голосового пресета доступен при блокировке.
- **Контроллеры:** привязка по MAC, отображение состояния связи и команда идентификации.

## Архитектура

Все устройства находятся в одной локальной сети через роутер 2,4 ГГц.

```text
Браузер ── HTTP ── Мастер ◄── UDP ── Пульт
                     │
                    UDP
                     │
               Слейвы и шлем
```

| Компонент | Назначение |
|---|---|
| **Мастер** | Хранит партитуру, синхронизирует планы исполнителей и управляет переходами сцен. Обслуживает веб-интерфейс. |
| **Слейв** | Исполняет свет и фонограммы: 12 DIM, 2 реле, отдельный AC-канал, UART-плеер YX6300 и WS2811. |
| **Шлем** | Отдельная прошивка: микрофон INMP441 → обработка I2S → DAC PCM5102A; управление лентой. |
| **Пульт** | Отдельная прошивка с двумя кнопками; передаёт команды мастеру, не хранит партитуру. |

Поддерживается до 10 назначенных приборов, включая шлемы. Пульт не занимает слот прибора.
Планы сцен загружаются на исполнителей; во время показа мастер передаёт команды перехода.
Браузер не нужен для переключения сцен физическим пультом.

Веб-часть — React/TypeScript/Vite. Прошивки — C++ с Arduino Core для ESP32.
Целевая плата — ESP32-S3 с 16 МБ flash и 8 МБ PSRAM.

## Важные границы

- В рабочей сети должен быть **один активный мастер**. Резервный мастер не обеспечивает
  бесшовный подхват текущего момента спектакля.
- При обычном включении мастер может запустить первую опубликованную сцену после
  готовности назначенных исполнителей. Шлем имеет автономный старт звука и света.
- Потеря Wi-Fi **не выключает** уже принятую сцену. Программный STOP не заменяет
  электрическое отключение опасной нагрузки.
- Управление рассчитано на доверенную LAN: HTTP без TLS, криптографической подписи
  обновлений нет. GPIO — логика 3,3 В; силовые нагрузки требуют подходящих внешних схем.
- Текущие исходники — **0.8.11**. Новый компактный UI подготовлен и проверен локально;
  это не означает установку этой версии на действующие платы.

## Разработка

Локальный редактор без подключения к ESP:

```sh
cd score-ui
npm ci
VITE_CONSOLE_BACKEND=0 npm run dev -- --host 127.0.0.1
```

Основные каталоги: `console/` — мастер и слейв, `helmet/` — шлем,
`remote/` — пульт, `score-ui/` — сайт, `tests/` — проверки, `tools/` — инструменты.
`control/`, `wifi04/`, `espnow/`, `radio/` и `snapshots/` содержат предыдущие реализации.

[Веб-часть](score-ui/README.md) · [Текущий UI](docs/OPERATOR_UI_0811.md) ·
[GPIO и история разводки](docs/PINOUT.md) · [История изменений](CHANGELOG.md)

Технические расследования и записи установок сохранены в `docs/` как история,
а не как описание сегодняшнего состояния всей системы. Программные и стендовые
проверки не заменяют испытания конкретной нагрузки.
