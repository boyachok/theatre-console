# Театральная ESP32-S3

**Подготовлена Консоль: прошивка0.7.0, интерфейс0.3.0.**
Новый профиль `console/`: React на мастере, партитура/версии/подтверждения,
локальные фейды ведомых, два реле, физические кнопки, идентификация/сброс сети.
Сборки/автотесты не заменяют стенд. Эта версия пока не записывалась на платы.
Инструкция: **[CONSOLE.md](CONSOLE.md)**. Лента ожидает уточнения электрического протокола.

По умолчанию `./deploy build master|slave` и `./deploy master|slave` используют
профиль `console`. Перед записью сверять MAC. Для прежнего профиля — `PROFILE=control`.

## Архив: отладочная IP-база 0.1.1

ESP32-S3 N16R8: flash 16 MB, PSRAM 8 MB OPI, RGB WS2812-совместимый GPIO48
(подтверждено миганием на тестовой плате). Одинаковая прошивка master/node;
роль, номер, сеть и список IP хранятся в NVS.

## Подключение к текущей плате

- Wi-Fi: **Stage-Setup-e385a0-v2**
- Пароль Wi-Fi: **debug123**, фиксирован в прошивке, не зависит от NVS.
- Веб: **http://192.168.4.1**, БЕЗ логина и пароля.
- Старую сеть Stage-Setup-e385a0 удалить из сохранённых сетей.

## Сборка и USB

Используются уже установленный Arduino CLI из Arduino IDE и esp32 core 3.3.11.

```sh
cd /Users/boyacheek/Projects/theatre-esp32
bash stage.sh build
bash stage.sh usb /dev/cu.usbmodem1101
bash stage.sh monitor /dev/cu.usbmodem1101
```

USB-скрипт закреплён за установленными версиями инструментов.
Проверен режим DIO, два OTA-раздела по 6 MB. Принудительный QIO ранее вызвал
ошибку ROM-загрузчика. После записи используется watchdog-reset: обычный RTS-reset
на этой плате иногда оставлял её в загрузчике. Версия 0.1.1 записана, запуск,
объёмы памяти и параметры точки подтверждены по USB Serial.

Если не удаётся подключиться к загрузчику: держать BOOT, нажать/отпустить RESET,
отпустить BOOT, проверить `ls /dev/cu.*` и повторить с актуальным портом.
USB-запись заменяет приложение и таблицу разделов. Важные прежние данные нужно
резервировать до первой записи.

USB Serial 115200: `i` — состояние и данные точки; `t` — временно переключить
GPIO RGB между 48 и 38. Подтверждённый GPIO сохранить через веб.
Старой команды d больше нет; пароля веб-входа нет.

## Настройка сети и мастера

В вебе выбрать роль и уникальный номер ведомого 1–10; указать SSID/пароль
роутера 2.4 ГГц. У всех 11 плат одна прошивка. У мастера выбрать роль «Мастер».
Установить одинаковый ключ группы (12–64 символа) на мастере и ведомых.
При пустых полях пароля сети и ключа их прежние значения сохраняются.

После подключения к роутеру точка настройки закрывается. IP смотреть в Serial
или списке клиентов роутера; закрепить его по MAC в DHCP. mDNS-имя печатается
в Serial. После 60 секунд без роутера точка настройки возвращается.

На мастере заполнить до 10 строк IP: строка 1 = ведомый 1 и т.д., пустая строка
пропускает позицию. Проверочные команды RGB отправляются через веб-пульт,
который показывает HTTP-ответ. Изоляция клиентов Wi-Fi должна быть выключена.

## OTA

В разделе обновления загрузить **build/firmware.ino.bin**, не merged.bin,
bootloader.bin или partitions.bin. Или с компьютера:

```sh
bash stage.sh build
bash stage.sh ota 192.168.1.101
```

Логин не нужен. Обычное OTA сохраняет NVS. Изменение разметки требует USB.
Не отключать питание. Подписи прошивок и автоматического rollback нет;
USB остаётся способом восстановления. OTA и связь 10 плат ещё не проверены.

## API

- GET /api/status — версия, номер и роль.
- POST /api/led — color=red|green|blue|off&blink=0|1, form-urlencoded.
- Заголовок X-Stage-Key: ключ группы, задаваемый в настройках.

## Границы этапа

Это база и проверка адресной связи, не готовая система сцен.
Пока нет сцен, кнопок пульта, синхронизации времени, ретраев/дедупликации,
heartbeat/failsafe, реле, MOSFET и аудиоплеера. Тестовые HTTP-команды синхронные,
не real-time. Перед шоу нужны подтверждения исполнения, безопасное выключение
при потере связи, аварийный стоп, защита OTA и тесты с 10 устройствами.
Управления 220 В в текущем коде нет.
