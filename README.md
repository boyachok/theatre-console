# Theatre console

Беспроводная театральная консоль: ESP32-S3 master, отдельный пульт remote, до10 одинаковых slave,
React-редактор партитуры и ручное переключение сцен.

## Что реализовано

- Горизонтальная партитура, числовые шаги, вертикальные сворачиваемые приборы.
- 12 независимых аппаратных диммеров25кГц: 8LEDC +4MCPWM; два дискретных реле,
  UART-аудиоплеер XY-V17B, адресная лента WS2811.
- Линейные световые/звуковые переходы, задержки реле, одинаковый трек вперёд без
  перезапуска, назад — заново. Фейды исполняются локально на slave.
- Свет/реле/звук переключаются кликом по ячейке. Звук включается выбранным файлом
  (сначала1), повторный клик ставитOFF; номер файла/уровни регулируются справа.
  Редактирование не выполняет сцену: запуск отдельно плеером.
- WS2811: wave/fill/static, RGB/GRB,800/400кГц, до1024 управляемых точек, асинхронныйRMT.
- Версионированная публикация, части партитуры поMAC, CRC, подтверждения приёма сцены,
  повторные команды не перезапускают переходы. Подтверждение не является датчиком нагрузки.
- Потеря связи не выключает уже запущенную сцену: fade заканчивается, состояние держится.
  После возврата связи — согласование сцены и fade-in аудио. Старые0.6 и0.4 ведут себя иначе.
- Реальные сетевые измерения, графики, идентификацияRGB и сброс реестра. Не выдумываются
  IP/пинг/RSSI/ACK. Выключение теста не останавливает обязательный сценовый обмен.
- Кнопки master: GPIO1 вперёд,GPIO2 назад; удержание3с — последний/первый. Дисплея нет.

- Отдельная прошивка `remote/`: GPIO13/14 — две кнопки наGND, короткие/3с-жесты,
  реальный мониторинг в «Сети», общий LED-статус и белая TX-вспышка80мс.
- Удаление сцены через собственный диалог: «не спрашивать до перезагрузки».
  Запрещённый браузером `window.confirm` больше не блокирует действия редактора.

## Начать

**[Актуальный пинаут и подключение WS2811](docs/PINOUT.md)** ·
[Первый стендовый запуск](CONSOLE.md) · [Пульт remote](docs/REMOTE.md) ·
[Версии и резервные копии](docs/VERSIONS.md)

```sh
cd score-ui
npm ci
npm run dev       # http://localhost:5173 — локальный макет, без связи с ESP
npm test
```

Прошивка: ESP32-S3 N16R8,16MB flash/8MB OPI PSRAM, Arduino ESP32 core3.3.11,
ArduinoJson7.4.3. Используется установленный Arduino CLI из Arduino IDE.

```sh
./deploy build master
./deploy build slave
./deploy build remote
# После проверки MAC; без подключённой опасной нагрузки:
./deploy master /dev/cu.usbmodemXXXX
EXPECTED_MAC=C0:4E:30:27:69:98 ./deploy slave /dev/cu.usbmodemYYYY
```

Сборки находятся в `build/console-{master,slave,remote}-wifi/`. Пульт — отдельный
`remote.ino.bin`; первичная USB-запись `./deploy remote USB_PORT`.
С0.7.6 есть служебный HTTP/OTA: `./deploy ota remote IP`, проверки role/MAC/token,
marker образа, фактического reboot. Старой0.7.2 для добавления OTA сначала нужен USB.
Для работы пульта мастер должен быть0.7.2. После записи открыть
`http://<IP мастера>/`: React встроен в образ, отдельная запись FS не нужна.
По умолчанию master проверяется поMAC `A0:85:E3:E2:BC:D4`; другой мастер требует
явного `EXPECTED_MAC`. Slave-образ не записывается на известныйMAC мастера.

Роутер2.4GHz, `YOUR_WIFI_SSID` / `YOUR_WIFI_PASSWORD`, интернет для работы не нужен. При обычной
записи сохранятьNVS. Имя USB-порта и DHCP IP не являются идентичностью платы.

## Репозиторий и бэкапы

Приватный GitHub: **https://github.com/boyachok/theatre-console**.

```sh
bash tools/backup.sh "Краткое описание изменений"
python3 tools/release.py --set 0.7.2  # перед следующей общей итерацией
```

Бэкап — явный commit/push; автоматического фонового отправителя нет. Скрипт
отказывается отправлять в публичный репозиторий. История содержит стендовые WLAN
настройки: не делать репозиторий публичным без очистки истории. Токены GitHub,
приватные ключи, node_modules и сборочные файлы не добавляются.
Партитуры с действующего мастера отдельно экспортировать вJSON: git-код не является
бэкапом изменяемой памяти уже работающей платы.

## Проверки и структура

`console/` — активные master/slave; `remote/` — отдельный пульт; `score-ui/` — React; `tests/` — ASan/UBSan,
wire/CRC,12каналов,WS2811,аудио,журнал и сжатое хранениеworkspace,потокиHTTP;
`tools/` — общая версия, встраивание веба и бэкап. GitHub Actions проверяет
синхронизацию версии, host-тесты и TypeScript/React-сборку.

Сохранены предыдущие профили: `control/`0.6, `wifi04/`0.4, `espnow/`0.3,
`radio/`0.2, `firmware/`0.1 и `snapshots/`. Их архивные номера/документы не
переписываются под новую общую версию. Для архива задавать `PROFILE=control` и т.п.
Старый транспорт ESP-NOW не взаимозаменяем с текущим Wi-Fi/UDP через роутер.
