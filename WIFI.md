# 0.6.0 — управление через Wi-Fi LAN

Актуальная логика выходов, матрица ON/OFF, настройки ведомых и совместимость: [CONTROL.md](CONTROL.md).
В 0.6 разбор/запись HTTP выполняются отдельной задачей, callbacks/UDP/actors принадлежат
управляющему loop(). Ожидания телефона не занимают heartbeat. HTTP/ACK измеряются отдельно;
устаревшие HTTP-команды отклоняются. Это не гарантия real-time, сцены/clock sync ещё нужны.

0.4.1 исправляет обнаруженное на железе раннее чтение MAC: сначала запускается
STA netif, затем читается MAC/задаётся hostname. Добавлено резервное чтение MAC.
USB-запись и запуск ведомого проверены; подключение к YOUR_WIFI_SSID пока не подтверждено.

## Сеть

Обе роли подключаются клиентами к внешнему роутеру:

- SSID: **YOUR_WIFI_SSID** (регистр важен)
- Пароль: **YOUR_WIFI_PASSWORD**
- ESP32-S3 использует 2.4 ГГц. Интернет не нужен.
- DHCP включён; устройства в одной подсети/VLAN, client/AP isolation выключена.
- Разрешить локальный UDP broadcast и UDP 4210 между клиентами, TCP 80 для веба/OTA.

Мастер больше НЕ поднимает Stage-Master-XXXXXX, ведомые не создают обслуживающие AP.
Фиксированного канала ESP-NOW нет: канал задаёт роутер. Автоматического создания
точки с таким же SSID при потере роутера нет — это создало бы конфликт сетей.
Параметры сохранены в `control/network_config.h`. Пароль в Serial/API не выводится.

## Прошивка и первый вход

```sh
cd /Users/boyacheek/Projects/theatre-esp32
./deploy master
./deploy slave
```

В чате команды те же: `deploy master` / `deploy slave`, одна плата на USB.
Нужно обновить обе роли и затем все используемые ведомые: UDP-версия не связывается
с ESP-NOW, даже при сохранённом внутреннем формате команд.

После записи USB Serial 115200, команда `i` показывает роль, connected, IP,
SSID, канал, RSSI и hostname. При connected=1 открыть `http://IP-мастера`.
Также доступен mDNS `http://stage-master-<последние-6-цифр-MAC>.local`, если роутер
не блокирует mDNS. Для прежнего мастера E2:BC:D4 это
**http://stage-master-e2bcd4.local**. При проблеме с mDNS использовать IP из Serial
или списка клиентов роутера. Телефон подключить к той же LAN.

Админка по-прежнему без логина. Интернет/облако/внешний брокер не используются.
Рекомендуется закрепить DHCP-адреса по MAC на роутере, но это не обязательно.

## Что сохранено

- PWM1–8 GPIO4/5/6/7/9/10/11/12, 25 кГц с 0.5.1, 8 бит, 0–255 (старые ведомые остаются на 1 кГц, 0.4.x имеют 4 канала).
- Реле GPIO8, только OFF/ON, прежняя настройка HIGH/LOW в NVS.
- Плеер: TX GPIO17, RX GPIO18, 9600/8N1; функции и UART-диагностика без изменений.
- RGB GPIO48, оценки связи, период heartbeat 500 мс, timeout ответа 400 мс,
  окно 120 попыток, цветовые пороги и дедлайн 100 мс.
- Нулевой старт и прямое управление без ARM на 0.5, локальное выключение по потере heartbeat; значения не восстанавливаются сами.
- До 10 ведомых, независимые подтверждения команд и до 4 передач с одним ID.
- Имена/номера по MAC и прежние настройки NVS, без стирания данных.

Не изменены namespace `radio-master`/`radio-slave` для старого списка устройств
и `stage-io` для конфигурации выходов. Слово radio в старом ключе NVS не означает
использование ESP-NOW. Старые MAC-записи без новой прошивки отображаются offline.

## Сетевой транспорт

Discovery мастера: UDP broadcast на адрес своей IPv4-подсети, порт **4210**, раз в
2 секунды. Ведомые отвечают unicast HELLO с небольшим случайным разносом.
Затем PROBE/ECHO, COMMAND/ACK и UART debug идут unicast на найденные локальные IP.

Управляющее тело v4 — 72 байта, мастер поддерживает v3/64 для старых 0.4.x; debug — 100 байт. Сверху добавлен 20-байтовый
LAN-конверт: magic/version/length/source MAC/destination MAC. UDP контролирует
целостность транспортным checksum. Это не криптографическая аутентификация.
Проверяются длины, обе сессии и ID команд. Конверт назначения не позволяет
случайно принять пакет другой платы при устаревшем DHCP-адресе.

Соответствие MAC -> IP обновляется по входящим пакетам. При отключении Wi-Fi или
смене собственного DHCP IP UDP-сокет пересоздаётся, таблица адресов очищается,
управляющая сессия обновляется. Старые команды не должны попасть в новую сессию.
При истечении lease ведомого его target ID также обновляется перед обработкой
накопившихся пакетов: задержавшаяся команда включения не должна отменить локальный failsafe.
После смены мастера/сессии выходы выключаются.

Wi-Fi переподключается автоматически, повторная попытка при отсутствии связи
примерно каждые 10 секунд. Выпадение одного ведомого не блокирует опрос остальных.
Отказ самого роутера означает потерю связи всей группы: ведомые должны уйти в OFF.

RTT теперь включает путь мастер -> роутер -> ведомый -> роутер -> мастер и
обработку приложениями. Это не односторонняя задержка. Timestamp приёма ставится
при чтении UDP приложением, поэтому очереди и задержки главного цикла входят в RTT.

**RSSI теперь другой по смыслу:** master = сигнал роутера, принимаемый мастером;
slave = сигнал роутера, принимаемый ведомым. Это не мощность прямого канала между
двумя ESP. В таблице подписи изменены, сами поля/пороговые значения сохранены.
Оценивать в первую очередь подтверждения, потери и дедлайны, а RSSI — запас связи.

## Панель

Основной экран и положения органов управления сохранены. Удалены статические
пояснения и предупреждающие надписи; остались кнопки, параметры и рабочие статусы.

- `/` — выбранный узел, pinned-статусы реле/звука/PWM и прямое управление.
- `/matrix` — матрица сендов по всем платам.
- `⚙` — настройки выходов и плеера, SSID/IP, имя/поиск платы, OTA.
- `/diagnostics` — все метрики, IP ведомых, старт/стоп замера, JSON-отчёт.
- `/uart?id=N` — TX/RX, HEX, ошибки и кнопки диагностического опроса.

Стоп пинг-теста останавливает сбор статистики, но не служебный heartbeat и статусы.
При новом старте замер очищается. Результаты RAM, при выключении мастера теряются.
Сетевой status JSON включает transport=wifi, SSID/IP/hostname/MAC и IP каждого узла.

## OTA

HTTP OTA работает по LAN IP каждого устройства. Кнопка OTA ведомого отправляет
ALL_OFF и открывает `/update` найденного адреса. Нужен свежий ответ ведомого.
URL привязан к target MAC; несовпадение на HTTP-странице/загрузке даёт 409, чтобы
устаревший DHCP-адрес не привёл к обновлению другой платы.

Бинарники:
- `build/control-master-wifi/control.ino.bin`
- `build/control-slave-wifi/control.ino.bin`

Не выбирать merged/bootloader/partitions. Строго правильная роль! Таблица разделов
не изменилась: два app по 6 MB, NVS сохраняется при обычном OTA.

```sh
./deploy ota master IP
./deploy ota slave IP
```

Перед записью ведомый локально выключает выходы. Rollback, проверка подписи/роли
самого бинарного образа и групповая передача файла мастером пока не реализованы.
Кнопка OTA ведомого — переход к его HTTP endpoint, не массовая прошивка через мастер.

## Сохранённые профили

```sh
PROFILE=espnow ./deploy master  # архив управления 0.3.1 ESP-NOW
PROFILE=espnow ./deploy slave
PROFILE=radio ./deploy master   # архив радиотеста 0.2.0
PROFILE=radio ./deploy slave
```

Нельзя смешивать UDP и ESP-NOW в одной рабочей группе. Архивы сохранены для
сравнения с роутером и отката по USB, не работают одновременно с Wi-Fi-профилем.

## Проверки

- Компиляция обеих ролей под esp32 3.3.11, DIO/16 MB, OPI PSRAM 8 MB.
- Хост-тесты: wire framing и bounds, destination MAC, DHCP peer updates,
  reconnect/IP-change generations, UDP errors, акторы/готовность, UART, совместимость 0.4.x и классификатор.
- UI: Chromium mobile размеры 390×844, 375×667, 320×568, основные команды,
  выбор узла, пауза измерений, UART; отсутствие статических примечаний.

**Физическое подключение к YOUR_WIFI_SSID, работа двух плат через роутер, 10 устройств,
реальные задержки/потери и OTA этой версии пока не проверены.** Сборка и mock-тесты
не заменяют проверку на площадке.

## Ограничения эксплуатации

Предупреждения убраны только из UI, ограничения проекта не изменились. GPIO не
допускают 5 В, аппаратные подтяжки/интерфейс реле обязательны, реле не управляется
PWM. Failsafe — программный, не аппаратный аварийный интерлок; зависание кода может
нарушить время реакции. STOP по UART не гарантирует отключение звука при неисправной
линии. Сеть должна быть доверенной: веб и OTA без логина, UDP без HMAC/шифрования
на уровне приложения, без защиты от подделки участника LAN. Не открывать порты
в интернет. Для эксплуатации нужны отдельные испытания и защита, а для сцен —
clock sync, предзагрузка, policy опоздавших событий и подтверждения исполнения.
